## Objective

Define the provider-independent tool and extension vocabulary: the
`ToolDescriptor` with its schema, capability identity, provenance, trust and
side-effect class, required approval, sandbox profile, credential audiences,
egress and budgets; toolsets as intersecting policy bundles; the deferred
search and describe operations that must not leak inaccessible tool names; the
capability RPC a bounded workflow uses; MCP client and server descriptors; the
signed extension manifest; the five hook classes with their distinct powers;
and secret-source descriptors.

This slice defines descriptors, grants and hook classes only. It executes no
tool, starts no MCP server, installs no extension, runs no hook and resolves no
secret. What it must guarantee is that no representable value grants more
authority than its class allows.

## Tool and extension contract

- A `ToolDescriptor` carries input and output schemas, capability identity,
  provenance digest, trust class, side-effect class, required approval,
  sandbox profile, credential audiences, egress policy, resource budget,
  platform support and the output or artifact contract. Every field is
  required; a descriptor missing a side-effect class or approval requirement is
  unrepresentable, because those two are what a policy decides on.
- Effective tools are the *intersection* of all applicable grants across
  tenant, profile, workspace, channel and automation. Intersection is the only
  combining operation exposed — there is no union, no override and no "grant
  wins" — so a messaging surface cannot inherit the CLI profile's breadth.
- Deferred search returns only authorized candidates. A tool the caller may not
  access is absent from results and from any error message, so search cannot be
  used to enumerate the registry. Search never mutates the session toolset;
  a toolset change is a durable event, not a side effect of looking.
- The workflow capability RPC is bounded by construction: eligible tool
  identities, maximum call count, time, CPU, memory and output budgets are
  fixed in the spec, recursion is unrepresentable, and self-invocation,
  delegation, arbitrary MCP access, approval decisions and privilege brokers
  are not reachable through the capability type. Nested calls carry actor, run
  and causation identities and remain subject to ordinary approval.
- MCP client descriptors carry transport, trust boundary, discovery timeout,
  per-tool filtering and explicit credential mapping. Server-initiated sampling
  is disabled by default and, when enabled, is representable only as a
  budgeted, policy-checked nested request that carries no implicit user
  authority. The MCP server export is capability-filtered; raw storage, hidden
  reasoning, credentials, unrestricted artifacts and broker input are
  unrepresentable in an export.
- An extension manifest is signed and content-addressed and declares type,
  entry points, supported protocol and schema ranges, contributions, required
  sandbox, files, network, credentials and resources, licence, publisher,
  provenance, update channel, configuration schema and migration behavior. A UI
  extension type cannot declare backend capabilities — the manifest types make
  that combination unrepresentable rather than merely rejected at runtime.
- Hook classes have distinct, non-widening powers: `observer` cannot change
  behavior; `filter` may reject with a typed reason but may not modify;
  `transformer` may return schema-validated bounded output; `context provider`
  may add labelled untrusted context within a budget; `workflow trigger`
  creates a durable input or action and never executes privilege inline. No
  hook class can approve, widen a sandbox, rewrite a historical message or
  block indefinitely — each is proven unrepresentable, and ordering, timeout,
  failure policy and causation are declared and deterministic.
- Secret-source descriptors return sealed values only. A command helper is a
  pinned executable with a closed argument schema and an empty environment; an
  arbitrary shell string is unrepresentable.

## Verification contract

| Check | Expected |
|---|---|
| Descriptor completeness | every `ToolDescriptor` field is required; a descriptor without side-effect class or approval requirement is unrepresentable |
| Grant intersection | intersection is the only combining operation; union, override and grant-wins are unrepresentable, proven over multi-scope grant fixtures |
| Search authorization | unauthorized tools are absent from results and from error messages; search cannot enumerate the registry or mutate a toolset |
| Workflow bounds | call count, time, CPU, memory and output budgets are fixed; recursion, self-invocation, delegation, arbitrary MCP, approval decisions and broker access are unreachable, proven by compile-fail coverage |
| Nested causation | every nested call carries actor, run and causation identities and remains subject to approval |
| MCP boundaries | sampling is off by default and, when enabled, carries budget and policy with no implicit user authority; raw storage, reasoning, credentials, unrestricted artifacts and broker input are unrepresentable in an export |
| Manifest completeness | every declared manifest field is required; a UI extension declaring backend capabilities is unrepresentable |
| Hook class powers | each class has exactly its declared power; approving, widening a sandbox, rewriting history and blocking indefinitely are unrepresentable for every class |
| Secret sealing | secret sources return sealed descriptors; an arbitrary shell command string is unrepresentable and command helpers require a closed argument schema and empty environment |
| Quality | workspace tests, strict Clippy and formatting pass offline with no new allowance, network access, runtime dependency or lockfile drift |

## Compatibility and evidence

Use only the permitted product requirements and synthetic fixtures.
`docs/product-plan/requirements/tools-extensions-and-hooks.md` § Canonical tool
runtime, § Programmatic tool composition, § Native MCP client and server,
§ Plugin and extension model, § Hook system and § Secrets and configuration
providers, together with
`docs/product-plan/requirements/state-and-protocols.md` § Tools, extensions and
MCP, are the sources. Record the grant-intersection matrix, the hook-class
power table with one covering case per prohibited action, and the compile-fail
cases for workflow escape and UI-extension backend authority.

## Stop conditions

Stop on any need for a new dependency or `Cargo.lock` change, an optional
side-effect or approval field, any grant combination other than intersection, a
search result or error revealing an unauthorized tool, a toolset mutated by
search, a reachable recursion or privilege path from the workflow capability, a
nested call losing causation, sampling enabled by default, a raw store or
credential reachable through an MCP export, a UI extension declaring backend
capability, a hook class able to approve or widen, an arbitrary shell command
in a secret source, a network or process call, a licence-boundary violation, a
forbidden clean-room input, or any path outside the lease.
