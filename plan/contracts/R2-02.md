## Objective

Prepare one immutable, attempt-bound protected handoff containing the canonical
R2-01 `RunSpec` and bounded prompt payload for `PromptDeliveryPlan::Stdin` or
`PromptDeliveryPlan::ProtectedReference`. The mechanism uses distinct anonymous
owned descriptors. Prompt bytes
are never copied or derived by this handoff into argv, environment, canonical
RunSpec bytes, durable state, a file name, `Debug`, display text or errors.

The handoff is declarative preparation for R2-05. It does not fork, execute,
select a child descriptor number, clear close-on-exec, install a sandbox, open a
network connection or prove that a descendant inherited the descriptors.
Credential values are outside this item: R2-41 owns sealed process-class
credential delivery, audience/version revalidation and revocation quarantine.
R2-02 proves that no credential-value input route exists.

## Protected handoff contract

### Canonical spec binding

- Construction accepts an already validated immutable `RunSpec`, encodes it
  with `RunSpec::to_canonical_bytes`, and binds the handoff to its canonical
  digest plus exact work, run, attempt, host, lifetime and backend coordinates.
- The spec channel contains exactly those canonical bytes. Reading the held
  descriptor, strictly decoding it with `RunSpec::from_canonical_bytes`, and
  re-encoding it produces byte-identical content and the bound digest.
- Spec and prompt channels have nominally distinct roles. Swapping them,
  truncating or appending bytes, or changing a coordinate, digest, delivery
  mode or protected/backend reference refuses before payload bytes are returned.
- Public metadata is immutable and value-redacted. It may expose typed
  coordinates, channel role, bounded length and the already-public RunSpec
  digest. It exposes no raw descriptor integer, path, prompt bytes or reusable
  credential/launch authority.

### Prompt modes

The R2-01 prompt plan remains the sole authority for shape:

- `Stdin` requires exactly one nonempty prompt payload of at most 65,536 bytes,
  with no embedded NUL, matching the existing agent request bound. The bytes
  occupy their own sealed descriptor, designated only for later stdin wiring.
- `ProtectedReference` requires one bounded prompt payload and the exact
  `ProtectedPromptReference` already carried by the RunSpec. The bytes occupy a
  distinct sealed descriptor whose metadata binds that exact reference. The
  opaque reference is never interpreted as a path. This transport binding does
  not authenticate the material or prove that an external record was resolved;
  upstream admission owns that decision.
- `BackendSession` accepts no local prompt bytes or prompt descriptor and binds
  only the already validated backend-session coordinate.

Missing, extra or transposed prompt material refuses. Arbitrary non-NUL bytes
within the stdin bound are preserved losslessly; they are not assumed UTF-8.

### Anonymous sealed descriptors

- The Linux implementation creates anonymous descriptors with
  `MFD_CLOEXEC | MFD_ALLOW_SEALING`, writes the complete bounded value, rewinds
  it, and installs exactly `F_SEAL_WRITE | F_SEAL_GROW | F_SEAL_SHRINK |
  F_SEAL_SEAL`.
- Before exposure it verifies descriptor type, exact length, current offset,
  close-on-exec and the complete seal set. A short write, allocation failure,
  changed seal set, wrong size or identity mismatch refuses and closes all
  owned descriptors.
- Prepared channel types own `OwnedFd`, are non-`Clone`, non-serializable and
  have value-redacted `Debug`. Raw integer conversion is not a public authority
  API.
- Reading uses positioned operations or an independently owned read position;
  one consumer cannot alter another channel's verification offset.
- Anonymous descriptors create no pathname or cleanup race. Mode-0600 named
  files, supervisor stores and protected sockets are future adapters, not
  fallback behavior in this item.
- Unsupported hosts fail with a typed refusal. The implementation never
  silently substitutes a temporary file, pipe, environment variable or argv.

### Ownership and consumption

- A prepared handoff moves once into `Taken` or `Aborted`; it has no public
  clone, replay, serialization or reset operation.
- Every attempted take consumes the Rust capability. A second take is
  unrepresentable or returns the exact `AlreadyConsumed` category.
- This discipline is not described as cryptographic or OS-global one-use:
  descriptor duplicates held outside the API are outside the claim.
- Abort, refusal and `Drop` close every descriptor owned by the handoff. One
  hundred prepare/consume/drop cycles and injected failures return the process
  descriptor count to baseline.
- All descriptors remain `CLOEXEC`. R2-05 alone may map a reviewed fixed child
  allowlist immediately before execution and must revalidate identity and
  containment then.

### Protected-data and authority boundary

- No constructor, field or accessor accepts a credential value. RunSpec
  credential bindings remain non-secret metadata only.
- No prompt or secret byte is copied to executable argv, environment, RunSpec,
  logs, errors, receipt metadata, durable spool or a filesystem path.
- Distinct synthetic fixture sentinels exercise both payload-bearing branches:
  `Stdin` and `ProtectedReference`. Each sentinel occurs once only in that
  mode's sealed prompt descriptor and zero times in `/proc/self/cmdline`, the
  inspected environment, canonical spec bytes, public metadata, `Debug`,
  display, errors, paths and durable state. This is evidence that the mechanism
  did not copy either fixture payload; it is not a claim that arbitrary
  caller-controlled argv or environment bytes can never equal prompt bytes.
- Anonymous sealed memory is immutable and path-free, not confidential from a
  same-UID debugger, `/proc` reader or duplicated descriptor. This item makes
  no such secrecy claim; later process/user/namespace boundaries provide it.
- Successful preparation grants no execution, sandbox, provider, credential,
  workspace, artifact, scheduler, network, transport or deployment authority.
  `Runner::run` and current adapter execution remain fail-closed.

## Verification contract

| Check | Expected |
|---|---|
| Spec bytes | a fully populated RunSpec is read from the spec descriptor, strictly decodes, re-encodes byte-identically and matches its bound digest |
| Prompt modes | 3/3 variants enforce their exact material shape; stdin and the exact protected reference carry lossless sealed payloads, backend session carries no payload descriptor |
| Prompt bound | both stdin and protected-reference modes accept exactly 65,536 arbitrary non-NUL bytes losslessly; in both branches empty, embedded NUL and 65,537 bytes refuse before descriptor creation; a mutation control proves both use the common bounded constructor |
| Seals | all four required seals and `CLOEXEC` are observed; write, grow, shrink and additional-seal mutations refuse |
| Binding | spec/prompt swap, truncation, append, wrong digest, work/run/attempt/host/backend/mode/reference mutations all refuse with exact categories |
| Encapsulation | compile-fail controls reject direct field construction, cloning, raw-FD extraction and credential-value arguments; paired typed reads compile |
| Leakage | distinct stdin and protected-reference sentinels each count zero in argv, environment, spec bytes, metadata, `Debug`, display, errors, paths and durable state, and one only in their own prompt descriptor |
| Descriptor discipline | unrelated high descriptors never enter the declared channel set; all prepared descriptors begin `CLOEXEC` |
| Cleanup | success, refusal, abort, drop and injected failure leave no filesystem residue and return descriptor count to baseline over 100 cycles |
| Concurrency | concurrent handoffs retain their own coordinates, digests and bytes and never cross-bind |
| Non-authority | a valid prepared handoff still receives the current typed runner containment refusal and no provider/adapter execution becomes available |
| Quality | focused, runner and workspace tests, strict Clippy, formatting, licence and diff checks pass locked and offline |

A fixed inert test helper may inspect `/proc/self/cmdline`, environment and its
negative open-descriptor set to prove no unintended inheritance. It receives no
model-produced command, performs no provider action and creates no public launch
API. Its evidence does not substitute for the R2-05 launch-time proof.

## Compatibility and non-goals

This item adds an internal protected transport boundary; it does not change the
RunSpec schema, agent/provider protocol, workspace/artifact model or existing
fail-closed execution. Binding supplied bytes to a protected reference is not
record lookup or authentication. This item does not resolve credential records,
rotate/revoke credentials, open executables, select argv/environment,
launch, map final child descriptor numbers, prove descendant containment,
create named runtime files, use supervisor stores or perform network I/O. R2-05
owns launch, R2-33 owns immutable launch identity and R2-41 owns process-class
credential material.

Permitted evidence is the checked-in product plan, current clean-room source,
synthetic fixtures, public Linux/nix APIs and test observations. Prior private
implementation source, reconstructed algorithms, real credentials and real
infrastructure identifiers are forbidden.

## Stop conditions

Stop if the handoff copies or derives any prompt material into argv,
environment, RunSpec, logs, errors, metadata, durable state or a file name; any
credential-value input route; public raw-FD/path authority;
clone/replay/reset; claiming that a caller-supplied payload proves authoritative
resolution; interpreting a protected reference as a path; fallback to named file, pipe, environment or
argv; clearing `CLOEXEC`; launch or child-inheritance claims; enabling runner or
adapter execution; same-UID confidentiality, credential freshness, containment
or attestation claims; a new dependency or lockfile change; unsafe-code/lint
weakening; network/private-archive access; licence-boundary crossing;
out-of-lease edits; or a failed required check whose repair is outside scope.
