## Objective

Define the durable vocabulary that makes prompt assembly explainable rather
than an opaque concatenation: the ordered, content-addressed `ContextManifest`
with per-component trust class and caps, the typed context references that
replace arbitrary host paths, compression as a durable lineage-bearing
operation, the tenant-scoped typed memory stores with provenance and
supersession, and the `LearningProposal` that keeps model-suggested learning
separate from reviewed publication.

This slice defines values, precedence and lineage only. It assembles no prompt,
counts no real tokens, fetches no URL, reads no file, runs no compression,
builds no index and activates no skill. Its central obligation is that
lower-trust content is structurally incapable of becoming policy.

## Context and memory contract

- A `ContextManifest` is an ordered list of components, each carrying source,
  trust class, byte and token caps, redaction result and content digest, plus
  the manifest's policy revision and token budget. A component without a trust
  class or digest is unrepresentable.
- Precedence is deterministic and total over trust classes, and it is
  enforced by type: a component of a lower trust class cannot override system,
  tenant, sandbox or approval policy. Retrieved documents and repository rules
  can *supply* task context and can never *become* policy — proven by
  compile-fail coverage, because this is the prompt-injection boundary.
- Workspace rule discovery is bounded to the registered workspace. A rule
  reference resolving above the workspace root, or into a parent or home
  directory, is a typed rejection. Provider-specific rule files are labelled
  compatibility inputs and carry a distinct trust class from the shared
  `AGENTS.md` format.
- Context references are typed — file with line range and artifact digest,
  folder with bounded depth and filter, diff, staged, commit, branch, url,
  session, turn, run, ticket, artifact and workspace. An arbitrary host path is
  unrepresentable. References carry resolved size and provenance and reject
  traversal, binary confusion, detected secrets and any change of
  authorization.
- Compression is a durable operation carrying source range, compressor provider
  and model, prompt or template digest, output digest, protected facts and
  verification status. It produces a *derived view*; the authoritative original
  messages remain addressable, and no compression operation can mutate or
  delete the audit transcript. Forking before compression is expressible.
- Token accounting separates estimated from provider-reported values per
  component class. The two are distinct types so an estimate can never be
  recorded as a measurement — an unavailable provider count is `null` with a
  reason.
- Memory stores are typed and tenant-scoped: user profile, workspace, team,
  task, episodic index and optional external provider bindings. Entries carry
  provenance, confidence, sensitivity, visibility, expiry or review date and
  supersession links. Correction supersedes rather than mutating; deletion
  follows retention rules and leaves a tombstone.
- Memory writes are revisioned proposals governed by actor and tenant policy. A
  proposal originating from model output carries a lower trust class by
  construction and has no path to raise its own trust or become policy. A
  `LearningProposal` carrying a candidate memory, skill patch or new skill is
  separate from published state, and an executable skill cannot be represented
  as auto-activated.

## Verification contract

| Check | Expected |
|---|---|
| Manifest completeness | a component without trust class, caps or digest is unrepresentable; the manifest carries its policy revision and budget |
| Precedence enforcement | a lower-trust component cannot override system, tenant, sandbox or approval policy, proven by compile-fail coverage |
| Rule discovery bounds | references above the workspace root or into parent/home directories are rejected; provider-specific rule files carry a distinct compatibility trust class |
| Reference typing | every listed reference kind round-trips; arbitrary host paths are unrepresentable; traversal, binary confusion, detected secrets and authorization changes are rejected |
| Compression lineage | compression records source range, model, template digest, output digest, protected facts and verification status; the authoritative transcript is unmutated and fork-before-compression is expressible |
| Token honesty | estimated and provider-reported counts are distinct types; an unavailable count is `null` with a reason and cannot be recorded as measured |
| Memory typing | all six store classes are representable and tenant-scoped; entries require provenance, confidence, sensitivity, visibility and retention |
| Supersession and deletion | correction supersedes rather than mutating; deletion leaves a tombstone and preserves the audit trail |
| Proposal isolation | a model-originated proposal carries a lower trust class with no path to raise it; an auto-activated executable skill is unrepresentable |
| Quality | workspace tests, strict Clippy and formatting pass offline with no new allowance, network access, runtime dependency or lockfile drift |

## Compatibility and evidence

Use only the permitted product requirements and synthetic fixtures.
`docs/product-plan/requirements/context-memory-and-learning.md` § Context
assembly, § Explicit context references, § Context budgets, caching and
compression, § Memory model and § Skills and learning loop, together with
`docs/product-plan/requirements/state-and-protocols.md` § Context, memory,
skills and profiles, are the sources. Record the trust-class precedence matrix,
the reference-kind coverage table and the compile-fail cases proving
lower-trust content cannot become policy. Synthetic content only; no real
workspace rules, session text or memory content appears in a fixture.

## Stop conditions

Stop on any need for a new dependency or `Cargo.lock` change, a component
without trust class or digest, any path by which lower-trust content overrides
policy, rule discovery reaching outside the registered workspace, a
representable arbitrary host path, compression that mutates the authoritative
transcript, an estimated token count recorded as measured, a memory entry
without provenance or retention, a correction that mutates instead of
superseding, a deletion that erases the audit trail, a model-originated
proposal that can raise its own trust or auto-activate an executable skill, a
network or filesystem read, a licence-boundary violation, a forbidden
clean-room input, or any path outside the lease.
