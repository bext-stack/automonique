## Objective

Enforce, in CI, that every Cargo package, crate, module, feature, binary,
schema name, metric, tracing target, fixture and release artifact carries the
`automonique-*` or `automonique_*` namespace, and that the only exceptions are
legacy compatibility codecs and forwarding executables explicitly listed in the
inventory. An undocumented legacy identifier fails the build rather than
becoming permanent by accident.

This slice implements the gate and its inventory binding. It renames nothing
that a migration contract has not already authorized, forwards no request and
changes no durable identifier. Where the gate finds a genuine violation, the
fix is the name — or an explicit inventory entry with its authorizing contract,
which is a decision, not a suppression.

## Gate contract

- The scan covers every namespaced surface: Cargo package and crate names,
  module paths, feature flags, binary names, schema and protocol names, metric
  names, tracing targets, fixture identifiers and release artifact names. A
  surface class that is not scanned is recorded as an explicit gap, so
  "the gate passes" never means "the gate did not look".
- The permitted exception set is exactly the inventoried legacy compatibility
  codecs and forwarding executables from `R1-17`'s registry. An identifier
  outside the namespace and outside that inventory fails CI, naming the
  identifier, its file and its surface class.
- The inventory binding is bidirectional: an inventory entry naming an
  identifier that no longer exists also fails, so the exception list cannot
  quietly accumulate dead permissions. Both directions are reported separately.
- The gate has no suppression comment, no allowlist file separate from the
  inventory and no environment variable that disables it. Adding an exception
  means adding an inventory entry with its authorizing migration contract,
  which is reviewable; a `#[allow]`-style escape hatch is exactly the mechanism
  `plan/doctrine.md` forbids for making a queue green.
- The gate is deterministic and offline: the same tree yields the same verdict
  and the same ordered findings, with no network access and no dependency on
  build order or filesystem iteration order.
- Failure output is actionable — identifier, location, surface class and the
  two ways to resolve it (rename, or inventory it with a contract). A finding
  that does not say how to resolve it produces a suppression instead of a fix.
- The gate proves it can still fail: a deliberately introduced non-namespaced
  identifier is rejected in a test, in the same way `BOOT-001` proves the plan
  gate can fail. A gate that has never failed is an untested assertion.

## Verification contract

| Check | Expected |
|---|---|
| Surface coverage | packages, crates, modules, features, binaries, schemas, metrics, tracing targets, fixtures and release artifacts are all scanned; any unscanned class is reported as an explicit gap |
| Namespace enforcement | an identifier outside `automonique-*`/`automonique_*` and outside the inventory fails CI naming identifier, file and surface class |
| Bidirectional inventory | an inventory entry for a no-longer-existing identifier also fails; the two directions are reported separately |
| No escape hatch | no suppression comment, separate allowlist file or environment variable can disable the gate, proven by attempting each |
| Determinism | the same tree yields identical ordered findings independent of build and filesystem iteration order, with no network access |
| Actionable output | every finding names identifier, location, surface class and both resolution paths |
| The gate can fail | a deliberately introduced non-namespaced identifier is rejected in a test |
| Authorized exceptions | every inventory exception carries its authorizing migration contract; an exception without one fails |
| Quality | workspace tests, strict Clippy and formatting pass offline with no new allowance, network access, runtime dependency or lockfile drift |

## Compatibility and evidence

Use only the permitted product requirements, the `R0-13` identifier inventory
and the `R1-17` registry. `.automonique/dev/guides/naming.md` supplies the
enforced rules; `docs/product-plan/reference/legacy-inventory.md` remains the
single sanctioned location for exhaustive legacy names. Record the per-surface
scanned counts, the finding counts in both inventory directions, and the
deliberate-failure demonstration. Report scanned-versus-total per surface class
rather than a single pass/fail, so partial coverage is visible instead of
implied.

## Stop conditions

Stop on any need for a new dependency or `Cargo.lock` change, a surface class
silently unscanned, any suppression comment, separate allowlist or environment
variable that disables the gate, a one-directional inventory binding, an
exception without an authorizing migration contract, non-deterministic or
order-dependent findings, a finding without a resolution path, a rename of a
durable identifier that no migration contract authorizes, a claim of passing
without the deliberate-failure demonstration, a licence-boundary violation, a
forbidden clean-room input, or any path outside the lease.
