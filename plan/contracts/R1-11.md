## Objective

Prove, on a deliberately hostile slice of the protocol, that TypeScript wire
types, runtime validators and low-level clients can be generated from
Rust-derived schemas reproducibly and without losing the four properties most
often lost in codegen: const bounds, discriminated unions, branded identifier
types, and forward compatibility with unknown events. The spike answers whether
the one-source-of-truth rule is achievable before `R8B` commits the SDK to it.

This is a decision spike with a recorded verdict, not a shipped generator. It
produces a representative slice, a reproducibility result, a per-property
result and an explicit recommendation with its residual risks. A spike that
reports only success has not been run adversarially.

## Spike contract

- Rust schemas are the source of truth. The slice is generated *from* the Rust
  protocol crate's emitted schema artifacts, never hand-written to match them.
  Handwritten TypeScript may add ergonomics but may not redefine a wire
  structure, and the spike records any place it was tempted to.
- The slice is chosen to be hard, not easy. It must include at least: a bounded
  string and a bounded integer with exact const limits, two distinct branded
  identifier domains, a discriminated union with three or more variants
  including one carrying no payload, a security-sensitive enum, a read-only
  enum, an optional-versus-nullable field pair, and an event type the generator
  has never seen.
- Const bounds survive generation. A generated validator must reject a value
  one byte or one unit over the Rust limit and accept the exact limit. A
  generated type that widens a bounded value to `string` or `number` without a
  runtime check is a recorded failure of this property, even if it compiles.
- Branded identifiers stay distinct. Assigning one domain's identifier to
  another's parameter must fail TypeScript compilation. A brand that exists at
  runtime but erases at compile time — or vice versa — is a partial pass and is
  recorded as such.
- Discriminated unions stay exhaustive. A `switch` over the generated union
  with a missing variant must fail type checking, and the payload-free variant
  must not degenerate into an optional-payload variant.
- Unknown-event compatibility holds. An event kind absent from the generated
  schema must decode into an explicit unknown representation preserving its
  raw bounded payload, matching the `R1-09` authority and `R1-03` enum rules —
  it must neither throw nor be silently dropped.
- Reproducibility is a zero-diff check: regenerating into a temporary tree from
  the same schema inputs produces byte-identical output, including file order,
  formatting and any embedded digest or timestamp. A generator that embeds a
  build time is a failure of this property, not a nuisance.
- The verdict is explicit and may be negative. `recommended`,
  `recommended with named constraints` and `not recommended` are all valid
  outcomes; each names the properties that passed, the properties that failed,
  and what the failure would cost `R8B`. An unmeasured property is recorded as
  `null` with a reason.

## Verification contract

| Check | Expected |
|---|---|
| Source direction | every generated artifact derives from the Rust-emitted schema; no hand-written type redefines a wire structure, and near-misses are recorded |
| Slice difficulty | the slice contains bounded string and integer limits, two branded domains, a three-plus-variant union with a payload-free variant, both enum classes, an optional/nullable pair, and an unseen event type |
| Bound preservation | generated validators accept the exact limit and reject one over, in both directions; a widened unchecked type is recorded as a property failure |
| Brand distinctness | cross-domain identifier assignment fails TypeScript compilation; runtime-only or compile-time-only brands are recorded as partial |
| Union exhaustiveness | a `switch` missing a variant fails type checking; the payload-free variant does not degenerate into optional-payload |
| Unknown-event tolerance | an unknown event kind decodes to an explicit unknown representation with its bounded payload preserved, and neither throws nor is dropped |
| Reproducibility | regeneration into a temporary tree is byte-identical including ordering, formatting and embedded digests; embedded build times are a failure |
| Verdict quality | the recorded verdict names passed properties, failed properties and the cost to `R8B`; unmeasured properties are `null` with a reason |
| Licence split | generated and harness code under `sdk/` carries `Apache-2.0`; Rust-side code carries `Elastic-2.0`; the split is recorded |
| Quality | workspace tests, strict Clippy and formatting pass offline with no new allowance, network access, runtime dependency or lockfile drift |

## Compatibility and evidence

Use only the permitted product requirements, the Rust protocol crate's own
emitted schemas and synthetic fixtures.
`docs/product-plan/requirements/typescript-sdk.md` § One source of truth is the
source for the authoritative direction, the emitted artifact list and the
zero-diff regeneration rule. Record the per-property result table, the exact
generator and toolchain versions, and the diff output of the reproducibility
run. An unavailable Bun or Node runtime makes the whole spike unmeasured —
record it as `null` with a reason rather than reporting a partial verdict as a
pass.

## Stop conditions

Stop on any need for a new dependency or `Cargo.lock` change, a hand-written
type standing in for a generated one, a slice narrowed to avoid a failing
property, a bound that survives only in a comment, a brand that erases in the
direction being tested, a generated union that is not exhaustive, an unknown
event that throws or is dropped, an embedded timestamp or non-reproducible
output, a verdict recorded as positive while a required property is unmeasured,
a network fetch, a licence-boundary violation, a forbidden clean-room input, or
any path outside the lease.
