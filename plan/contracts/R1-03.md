## Objective

Implement the length-delimited frame codec and version negotiation used by
every local Automonique socket: a bounded length prefix, a decoded envelope
carrying protocol name, major version, request identifier and message kind, and
a closed error vocabulary that distinguishes a malformed frame from an
unsupported peer. Size and nesting limits are enforced *before* deserialization
so a hostile or oversized body is rejected without ever being parsed.

This slice defines framing, envelope, negotiation and errors only. It opens no
socket, verifies no peer credentials, performs no authorization, reads no
clock, resolves no spool reference and implements no message handler. Newline
framing is not implemented at all — model text may contain any byte, and a
delimiter that can appear inside a payload is not a delimiter.

## Codec contract

- Every frame is a fixed-width big-endian unsigned length prefix followed by
  exactly that many payload bytes. The maximum frame length is a public
  constant; a prefix declaring more is rejected before any allocation sized by
  it. A reader never trusts the declared length to reserve memory.
- Partial frames are a resumable state, not an error: the decoder reports how
  many bytes it still needs and never consumes a frame it has not fully
  received. A frame is delivered exactly once and the consumed byte count is
  exact, so a stream of concatenated frames decodes to the same sequence
  regardless of how the underlying reads were chunked.
- The decoded envelope carries `protocol`, `version`, `request_id` and `kind`.
  An unknown `protocol` name and an unsupported major `version` both fail
  closed with distinct typed errors; neither is downgraded, guessed or
  defaulted.
- Additive unknown fields are accepted within a supported major version.
  Security-sensitive enums reject unknown values; read-only enums decode an
  unrecognized value into an explicit `unknown` representation that preserves
  the original spelling for logging without granting it meaning. The choice
  between the two is a property of the field's declaration, never of the
  caller.
- Nesting depth is bounded by a public constant and enforced during decode, so
  a deeply nested body fails at a known depth rather than by exhausting the
  stack. Depth, length and byte-count limits are separately configurable public
  constants with independent errors.
- Version negotiation compares a locally supported inclusive range against a
  peer's advertised range and yields either the highest common major version or
  a typed no-overlap error naming both ranges. An empty or inverted range is a
  construction error, not a negotiation outcome.
- Large event bodies are referenced by sequence and offset, never copied
  through the control frame. The codec carries the reference as an opaque
  bounded value and does not resolve, open or validate the spool it names.
- Every rejection maps to a stable typed error category with a documented
  mapping to a wire error code, so a peer receives the same classification a
  local caller sees. Error text names the field and violation class and never
  echoes the offending payload bytes.

## Verification contract

| Check | Expected |
|---|---|
| Frame boundaries | exact-limit, one-byte-over and zero-length frames pass or fail as declared; concatenated frames decode identically under every read chunking, including one byte at a time |
| Partial input | a truncated prefix and a truncated body both report a resumable need-more state with an exact remaining count and consume nothing |
| Allocation safety | an oversized declared length is rejected before allocation, proven by a decoder that never reserves memory from an untrusted prefix |
| Envelope negotiation | unknown protocol names and unsupported major versions fail closed with distinct errors; overlapping ranges resolve to the highest common version; inverted and empty ranges fail at construction |
| Enum discipline | unknown security-sensitive enum values are rejected; unknown read-only values decode to `unknown` preserving the original spelling |
| Nesting and limits | depth, length and byte ceilings fail independently with their own error category at the exact declared boundary |
| Error mapping | every typed error has one stable wire code, the mapping is exhaustive over the error enum, and no message contains payload bytes |
| Quality | workspace tests, strict Clippy and formatting pass offline with no new allowance, network access, runtime dependency or lockfile drift |

## Compatibility and evidence

Use only the permitted product requirements, the structural migration map and
synthetic fixtures. `docs/product-plan/requirements/state-and-protocols.md`
§ Versioning rules is the source for the envelope, the fail-closed rules and
the prohibition on newline framing. Record the accepted and rejected case
counts per limit and the full error-category table. A compatibility decoder for
a `legacy.*` v1 envelope may be added only as an explicitly inventoried
compatibility codec; it is never emitted for a fresh installation, and its
presence is recorded rather than assumed.

## Stop conditions

Stop on any need for a new dependency or `Cargo.lock` change, an unbounded
read or a length-driven allocation, newline or any in-band delimiter framing, a
depth or size limit that is not a public constant, an unknown protocol or major
version that decodes rather than failing, a security-sensitive enum that
accepts an unknown value, an error message containing payload bytes, a
non-exhaustive error-to-wire-code mapping, a clock or socket read, a
licence-boundary violation, a forbidden clean-room input, or any path outside
the lease.
