## Objective

Define the peer authorization decision and the runtime directory layout rules
that protect every local Automonique socket: a typed peer credential carrying
the connecting UID, GID and PID, a total decision function that admits or
refuses that credential against a declared policy, and the mode and ownership
invariants for the runtime tree. Peer credentials are verified *before* request
parsing, so an unauthorized peer never reaches the codec.

This slice defines credentials, policy, decisions, path invariants and errors
only. It creates no socket, calls no `getsockopt`, reads no filesystem, spawns
no process and performs no role or tenant authorization — that is `R1-13`. It
supplies the rules a later transport applies, and a rule that cannot be
evaluated offline is not in this slice.

## Authorization contract

- A peer credential is a validated value carrying UID, GID and PID. It is
  constructible only from explicit components; there is no default, no
  ambient-authority constructor and no `From<()>`. A credential is evidence
  supplied by the kernel to a transport, never something a message body can
  assert.
- The decision function is total over credential and policy and returns a typed
  `admit` or a typed refusal naming exactly one reason. There is no boolean
  return and no path on which an error is interpreted as admission. Absent or
  unavailable credentials are a refusal reason, never a default admit.
- Policy admits an explicit UID set, optionally an explicit GID set, and never
  a wildcard. Root is not implicitly trusted: if a policy admits UID 0 it says
  so explicitly, and the refusal reason distinguishes "not in the admitted set"
  from "credentials unavailable".
- PID is recorded as diagnostic provenance and is never sufficient for
  admission on its own. A PID may be reused between the kernel's observation
  and any later use, so no rule may key authority on it.
- The runtime layout declares required permission bits per entry: the host
  directory and attempt directories are `0700`, the control socket and mutable
  status, event and log files are `0600`, and the immutable sanitized host spec
  is `0400`. A checker evaluates an observed mode/owner triple against the
  declared requirement and refuses anything more permissive than declared —
  equal-or-stricter is not accepted either where an exact mode is required, so
  drift in both directions is visible.
- Path rules reject symlinked components, unexpected ownership, world- or
  group-writable parents, embedded NUL, path escapes above the runtime root and
  non-canonical traversal. The rules are expressed over supplied path metadata
  so they are testable without touching a real filesystem.
- Every refusal maps to a stable typed category. Refusal text names the rule
  and the violating class only; it never contains the socket path, the peer's
  full command line or any credential value beyond the numeric IDs already
  known to both sides.

## Verification contract

| Check | Expected |
|---|---|
| Credential construction | credentials require explicit components; no default or ambient constructor exists, proven by compile-fail coverage |
| Decision totality | the decision is exhaustive over credential and policy, returns exactly one typed reason on refusal, and has no path where an error yields admission |
| UID and GID policy | admitted, unadmitted, root-when-admitted and root-when-not-admitted cases resolve as declared; a wildcard policy is unrepresentable |
| PID is not authority | no admission path depends on PID; a policy attempting to admit by PID alone fails at construction |
| Mode and ownership | `0700`, `0600` and `0400` requirements pass at the exact declared mode and fail on any more-permissive or otherwise-differing observed mode |
| Path safety | symlinked components, wrong owner, writable parents, embedded NUL, escapes above the runtime root and non-canonical traversal are each refused with their own category |
| Refusal hygiene | every refusal category is reachable in test, and no refusal message contains a socket path or command line |
| Quality | workspace tests, strict Clippy and formatting pass offline with no new allowance, network access, runtime dependency or lockfile drift |

## Compatibility and evidence

Use only the permitted product requirements, the structural migration map and
synthetic fixtures. `docs/product-plan/requirements/state-and-protocols.md`
§ Versioning rules and § Execution-host filesystem are the sources for
credential-before-parse ordering and the mode table. Record the admitted and
refused case counts per rule and the full refusal-category table. If a real
socket is used anywhere in test, record that fact explicitly — an offline rule
layer that quietly depends on a live kernel feature has not been verified as a
value layer.

## Stop conditions

Stop on any need for a new dependency or `Cargo.lock` change, a decision
function that is not total, any path where an error or missing credential
yields admission, a wildcard or implicit-root policy, admission keyed on PID, a
mode rule that accepts a more-permissive observed mode, a filesystem or socket
read inside the value layer, a refusal message containing a path or command
line, a licence-boundary violation, a forbidden clean-room input, or any path
outside the lease.
