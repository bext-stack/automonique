## Objective

Evolve the existing runner spool into the sole private durable writer for one
exact RunSpec attempt. It appends ordered canonical runner events with embedded
bounded raw-provider records, preserves stdout and stderr as separate raw
streams, exposes exact cursor
replay, publishes status through atomic replacement, recovers deterministically
after interruption, and charges all bytes to the RunSpec spool budget.

The writer stores and validates observations only. It does not launch or call a
provider, normalize vendor data, classify provider output as authoritative,
resolve artifacts, own daemon business state, delete retained data or report a
run complete to the daemon.

## Spool contract

### Canonical ownership

- One spool binds exact work/run/attempt/host coordinates and canonical RunSpec
  digest. Its quota is only `RunSpec::spool_budget_bytes()`.
- Provider-normalized observations reuse the canonical R1-09 `PreviewEvent`,
  `RecordedEvent`, `EventKind`, `Authority` and `RawProviderRecord` types. The
  current runner-local five-kind `EventKind`, duplicate `Authority` and magic
  terminal payload are retired from the fresh format.
- A runner-owned outer spool record binds the immutable attempt coordinates to
  exactly one closed body: `Preview(PreviewEvent)`,
  `Recorded(RecordedEvent)`, or `Lifecycle(RunnerLifecycleEvent)`. The
  lifecycle kind is exactly `started`, `heartbeat`, or `cancel_requested` and
  carries no arbitrary payload. It supplies the runner-only kinds required by
  the product without pretending they are provider-normalized `EventKind`s.
- Narrow protocol changes may add only lossless read-only event projections
  required for encoding. They may not add authority, mutate events, infer a
  terminal outcome absent from the canonical event, or introduce a second
  schema.
- `PreviewEvent` remains preview and cannot produce terminal state.
  `RecordedEvent` preserves its explicit authoritative or synthetic authority.
  Every canonical recorded event kind is accepted exhaustively.
- `RawProviderRecord` is preserved losslessly through its current inline bound
  or bounded artifact-digest coordinate. That coordinate is recorded but never
  authenticated, opened or resolved here.

### Filesystem boundary

- The writer consumes a caller-supplied owned pre-opened directory descriptor,
  not an arbitrary caller path. It grants only the storage location and no
  launch or process authority. The directory is an effective-UID-owned,
  non-symlink directory with mode `0700` and stable device/inode identity.
- Fixed relative entries only: `manifest.json`, `events.ndjson`,
  `stdout.ndjson`, rotated stderr segments, `status.json`, and the sole fixed
  implementation temporary `.status.next.tmp`.
- Every file is opened fd-relative with no-follow and close-on-exec semantics,
  is regular, effective-UID-owned, link-count one and mode `0600`. Named
  operations revalidate the held directory identity. Renaming or replacing the
  external pathname cannot redirect operations away from that held inode;
  without a parent/name capability the writer does not claim to observe the
  external replacement itself.
- Exactly one nonblocking exclusive writer lock exists. A second writer refuses
  without mutation. The lock is held on the validated open `manifest.json`
  description for the writer's lifetime; no extra lock pathname exists. This
  item never deletes retained spool records.
- Fd-relative operations use the already-locked public `rustix` 1.1.4 through a
  direct runner dependency. That package/version is already in `Cargo.lock`;
  adding the direct edge may update only the runner dependency list in the lock.
  No unsafe wrapper, `/proc/self/fd` reopen or path fallback is permitted.
- The only removable implementation entry is a validated fixed
  `.status.next.tmp`: one component, regular file, effective-UID-owned, link
  count one, mode `0600`, opened exclusively beneath the held directory. On
  recovery, an exact leftover temporary is validated by fd/inode before removal.
  Uncommitted final-record bytes may be truncated as specified below; no
  committed journal, segment, manifest or status is deleted.

### Immutable binding and exact encodings

Fresh creation exclusively writes, syncs and directory-syncs `manifest.json`
before any channel record. Its closed canonical JSON object has exactly these
keys and values:

```text
{"attempt_id":S,"host_id":S,"run_id":S,"run_spec_digest":D,
 "schema":"automonique.runner.spool-binding/v1","work_id":S}
```

`S` is the exact canonical typed coordinate spelling and `D` is the canonical
RunSpec SHA-256 digest. Existing creation refuses; recovery requires exact
manifest grammar, owner/mode/type/link checks, and exact equality with the
offered RunSpec coordinates and digest. Thus an empty spool is still bound and
recoverable without trusting `status.json`.

Every durable object uses protocol canonical JSON key ordering and types.
Unsigned quantities are canonical decimal strings matching
`0|[1-9][0-9]{0,19}`. Signed epoch milliseconds are canonical decimal strings
matching `0|-?[1-9][0-9]{0,18}` and must parse exactly as `i64`. Digests are
lowercase `sha256:` strings. Byte payloads use the canonical hex-fragment form
below. NDJSON adds exactly one `\n` after each complete
canonical object, and payload text/bytes are fields inside that object rather
than framing.

`events.ndjson` records have this exact closed envelope:

```text
{"attempt_id":S,"body":EventBody,"chain_digest":D,"host_id":S,
 "previous_digest":D,"run_id":S,
 "schema":"automonique.runner.spool-event/v1","sequence":U}
```

`EventBody` is one of the following exact closed objects; every inactive
optional coordinate is present as `null`:

```text
{"at_millis":I,"coordinates":Coordinates,"kind":"preview",
 "text":S}
{"at_millis":I,"authority":"authoritative"|"synthetic",
 "coordinates":Coordinates,"event_kind":EventKind,
 "kind":"recorded","raw":null|RawProviderRecord,
 "source_schema_version":U,"terminal_outcome":null|TerminalOutcome}
{"at_millis":I,"authority":"synthetic","kind":"lifecycle",
 "lifecycle_kind":"started"|"heartbeat"|"cancel_requested"}
Coordinates={"item":null|S,"session":S,"turn":null|S}
```

`TerminalOutcome` is exactly `completed`, `failed`, `cancelled`, `timed_out`,
or `lost`. It is mandatory exactly when `event_kind` is `run_terminal` and
forbidden otherwise. It is the runner's bounded stored observation supplied
with the terminal record, not an inference from provider bytes and not daemon
business-state authority. The implementation records its actual R1-09
`Authority`; neither outcome nor authority is defaulted.

`RawProviderRecord` is encoded as the exact lossless projection

```text
{"binary":{"digest":D,"schema_digest":null|D,"version":S},
 "payload":{"artifact_digest":S,"inline_hex_chunks":null}
          |{"artifact_digest":null,"inline_hex_chunks":[H32]},
 "source_cursor":S,"source_type":S}
```

where both payload keys are always present and exactly one is non-null.
`H32` is a lowercase even hex string decoding to at most 32,768 bytes, so its
encoded string is within protocol `MAX_JSON_STRING_BYTES`. Empty inline payload
is exactly `[]`; nonempty inline bytes use one or two fragments, every nonfinal
fragment decodes to exactly 32,768 bytes and the final fragment to 1..=32,768.
This is the sole fragmentation and removes alternate byte spellings.
Read-only protocol projections may expose the existing optional provider turn,
item, provenance schema digest and raw-payload fields needed to reproduce these
values; no constructor or authority changes.

The event chain is exactly:

```text
genesis = 32 zero bytes
content = canonical bytes of the spool-event object with the
          previous_digest and chain_digest keys removed
chain_digest = SHA256("automonique.runner.spool-event/v1" || 0x00 ||
                      previous_digest_raw_32 || content)
```

The stored `previous_digest` is the lowercase `sha256:` rendering of the raw
previous value, including `sha256:` plus 64 zeros at genesis. The computed
digest is inserted only after hashing, so the preimage is not circular.

All `at_millis` values preserve the full existing `EpochMillis` domain. Literal
fixtures cover `i64::MIN`, `-1`, `0` and `i64::MAX`; leading zero, plus sign and
negative zero refuse.

Raw stdout/stderr chunk records use this exact closed object:

```text
{"attempt_id":S,"chain_digest":D,"chunk_sequence":U,"offset":U,
 "payload_hex_chunks":[H32],"previous_digest":D,"run_id":S,
 "schema":"automonique.runner.raw-chunk/v1",
 "stream":"stdout"|"stderr"}
```

Chunk sequence begins at one and offset at zero independently per stream;
each next offset equals prior offset plus decoded payload bytes. Each decoded
chunk is at most 65,536 bytes. Raw provider records remain embedded only in
their recorded normalized event and are not silently copied into stdout.
Raw stream chunks are nonempty and therefore contain one or two canonical
fragments under the same nonfinal/final rule.
Each raw stream has its own zero genesis and the same chain construction using
domain `automonique.runner.raw-stdout/v1\0` or
`automonique.runner.raw-stderr/v1\0` and canonical chunk content with both
digest keys removed.

`status.json` has this exact closed object:

```text
{"attempt_id":S,"charged_bytes":U,"event_chain_digest":D,
 "host_id":S,"last_sequence":U,"run_id":S,
 "run_spec_digest":D,"schema":"automonique.runner.status/v1",
 "state":"empty"|"nonterminal"|"terminal"|"reconciliation_required",
 "terminal_outcome":null|TerminalOutcome}
```

The terminal outcome is non-null exactly for `terminal`; it is null for all
other states. In `empty`, `event_chain_digest` is the zero genesis spelling and
`last_sequence` is zero. `charged_bytes` is the least stable value satisfying
`charged_bytes = bytes(all other persistent entries) + bytes(status.json with
that charged_bytes spelling)`; the bounded decimal digit transition is computed
with checked arithmetic before writing. A checked-in independently authored literal fixture for each
manifest/event-body/raw/status shape, including null branches and all terminal
outcomes, must parse, re-encode byte-identically and carry an independently
calculated chain digest. Encoder-vs-decoder self-roundtrip is not sufficient.

Fresh creation eagerly creates only the durable `manifest.json` and initial
`status.json`; events, stdout and stderr files are created lazily on their first
transaction. Creation returns only after manifest, initial empty status and the
held directory have been synced. Exact runner-minimum 4,096-byte budget creation
must succeed. Each later transaction preflights its full new durable record,
the next status fixed point and old-plus-temporary peak; exactly one byte less
than that transaction requires refuses before mutation.

Every preview text is at most 65,536 UTF-8 bytes. Every JSON string therefore
fits protocol `MAX_JSON_STRING_BYTES`. Every complete encoded event
record including its newline is at most 524,288 bytes; every complete encoded
stdout/stderr chunk record is at most 196,608 bytes. The encoder checks decoded
payload/text and complete encoded bounds before durable allocation or mutation.

### Normalized event journal

- The outer envelope sequence is the offered `PreviewEvent` or `RecordedEvent`
  sequence and must equal one after the preceding outer sequence. A lifecycle
  append likewise offers its sequence. The writer validates rather than
  rewriting the private canonical value. Duplicate, gap, regression, overflow,
  wrong envelope run or wrong attempt refuses.
- Timestamp is UTC epoch milliseconds but is never the ordering authority and
  need not be monotonic across clock changes.
- Each complete record includes a domain-separated SHA-256 chain over the
  preceding digest and complete canonical record. The chain detects mutation
  and reordering; it is not a signature or provenance proof.
- There is exactly one typed `RunTerminal` event with its required closed stored
  outcome and nothing may follow it. Spool status preserves that supplied typed
  observation; it never infers an outcome from magic opaque bytes. A preview
  cannot select or change terminal state.
- Arbitrary text and bytes are encoded losslessly inside closed bounded records;
  raw model data is never used directly as newline framing. Preview text is
  admitted at a spool-local maximum of 65,536 UTF-8 bytes before record
  allocation even though its protocol value constructor is currently broader.

### Raw channels and shared budget

- `stdout.ndjson` carries byte-lossless bounded raw chunks with the exact raw
  schema above and an independent monotonic offset/sequence/digest chain.
- Stderr carries byte-lossless chunks in at most 256 ordered segments named
  `stderr.00000000.ndjson` through `stderr.00000255.ndjson`. Each segment has an
  exact 4-MiB encoded-byte ceiling. Rotation atomically closes and syncs one
  segment before exclusively creating the next; no segment is overwritten,
  wrapped or deleted. The shared RunSpec budget can stop stderr earlier.
- A complete pre-encoded chunk record is never split. If it does not fit a
  nonempty active segment, the old segment is synced before the next contiguous
  final name is exclusively created and directory-synced. Failure to fit after
  segment 255 returns `stderr_segment_limit` before mutation even if aggregate
  budget remains. Recovery requires contiguous segment names; only the final
  segment may have an incomplete crash tail, and earlier segments are immutable.
- Embedded NUL and every split of a multibyte UTF-8 sequence round-trip
  unchanged. UTF-8 is not assumed for raw channels.
- Inline raw data uses the protocol's existing 65,536-byte ceiling; a larger
  raw provider record requires its typed artifact reference or refuses.
- Manifest, events, stdout, stderr and status share one checked aggregate ledger
  derived from the RunSpec spool budget. Charged bytes are exact logical bytes
  in those files, including NDJSON newlines; directory
  entries, filenames and filesystem allocation blocks are excluded because they
  are not portable byte measures. During status replacement, the quota charges
  the existing durable files plus the entire new temporary until rename removes
  the old status. Expected quota failure is preflighted before channel mutation.
  Exact limit succeeds; one byte over or arithmetic overflow refuses with no
  channel mutation.
- Fresh creation preflights the complete manifest and initial empty-status
  fixed point before creating either. After manifest durability, any incidental
  I/O failure leaves a bound recoverable creation rather than an unbound healthy
  spool; recovery completes or returns a typed failure without guessed cleanup.
- A replay after lost receipt is exact and per stream. Offering an already
  committed sequence/offset with byte-identical content and digest returns the
  original immutable receipt without mutation. The same identity with different
  content conflicts; a new identity must be the exact next sequence/offset.

### Durable append and status

For each record the writer:

1. validates identity, authority, kind, terminal state, bounds and quota;
2. produces the complete closed bytes;
3. appends them to the owning stream;
4. calls `sync_data` on that stream;
5. advances committed sequence/digest/budget in memory;
6. derives status only from committed normalized events;
7. exclusively writes the fixed validated `0600` `.status.next.tmp`;
8. syncs the temporary, atomically renames it to `status.json`, then syncs the
   containing directory;
9. returns an immutable receipt only after all preceding steps complete.

The immutable replayable receipt binds only channel, run/attempt, committed
sequence or byte range and record digest. Current persistent charged bytes and
the current transaction's peak reserved bytes are returned as a separate
non-replayed accounting observation; they are metrics, not receipt identity,
because cross-stream append order is not durably journaled. The receipt is
storage evidence, not provider or business-state authority. If a record becomes
durable but its receipt is lost, the caller performs the exact replay above; it
does not append blindly again.
After stream sync succeeds but status/receipt publication fails, the live writer
latches that pending transaction. Until byte-identical replay completes it,
every altered replay or new append refuses; the other valid path is to close and
recover. A failure cannot silently advance to a second append.

### Restart and corruption

- Reopen scans incrementally with bounded memory. It never uses `read_to_end`
  over a potentially one-gigabyte spool.
- It verifies exact grammar, identities, sequences/offsets, limits and digest
  chains. Only an incomplete final record may be truncated to the last verified
  boundary, synced and reported as crash-tail recovery.
- A corrupt complete record, mutation, interior deletion, insertion, reorder, wrong
  identity, invalid encoding, oversized record, second terminal or post-terminal
  record refuses and remains on disk for reconciliation; it is not truncated
  into apparent health.
- Loss of a complete suffix cannot be authenticated by this local chain. A
  final non-newline-delimited suffix is defined as uncommitted crash tail and
  may be truncated. A valid shorter chain or missing whole journal is never
  reported healthy/running; recovery returns `reconciliation_required`. The
  item does not claim to distinguish crash loss from malicious same-UID suffix
  deletion without an external committed-head anchor.
- The status cache anchors only the normalized event head. Deleting a complete
  stdout/stderr suffix or an entire raw stream can leave a valid shorter chain
  indistinguishable from a history in which those bytes were never written.
  That loss is explicitly undetectable without an external raw committed-head
  anchor and is never claimed as corruption detection. If some observable
  status/event inconsistency also exists, recovery is reconciliation-required;
  otherwise the writer reports only the verified remaining raw facts.
- `status.json` is only a cache. Missing, stale, partial or corrupt status is
  rebuilt atomically from the journal. Status ahead of the journal is never
  trusted. A terminal journal reconstructs its exact typed stored outcome.
- Fault injection before/after stream sync, temporary sync, rename and
  directory sync converges to the prior or complete new committed state, never
  a fabricated terminal state.
- Stderr rotation additionally injects failure before/after new-segment
  exclusive creation, directory sync, first append and segment sync. Recovery
  selects the prior segment or the complete next one and never exposes a gap,
  overwritten segment or uncharged complete record.
- The API distinguishes `create` from `recover`; there is no generic open that
  silently chooses. Recovering nonterminal history does not prove a live
  process. It atomically republishes `reconciliation_required` and returns a
  typed recovery disposition containing only verified storage facts. A later
  reconciler may supply authoritative host/provider evidence; this writer does
  not transition the status back to nonterminal or claim resumability. An
  already-owned in-process writer never reopens itself to simulate recovery.

### Cursor and protected-data semantics

- Cursor reads are pages, never an unbounded full-suffix `Vec`. A request carries
  `after`, `max_records` and `max_encoded_bytes`. Record count is in `1..=1,024`;
  encoded bytes are in `524,288..=1,048,576` for normalized events and
  `196,608..=1,048,576` for raw streams, so one admitted record always fits. A
  response returns the bounded suffix that fits
  plus `next_cursor` and `more`; zero begins the first page, middle begins
  strictly later, last returns an empty page, and ahead refuses. A single record
  is smaller than the page-byte ceiling, so pagination always makes progress.
  Normalized and raw cursors remain distinct namespaces.
- R2-03 performs no retention, so cursor expiry cannot occur. Future pruning
  must return `resync_required`, never a silent partial suffix.
- No credential-value input is introduced. Errors, status, filenames, receipts
  and `Debug` never contain event/stdout/stderr payload bytes.
- The spool cannot prove arbitrary provider bytes secret-free. Upstream adapters
  own that admission; this item performs no content-based secrecy claim.
- Ownership/mode protects against other users, not same-UID readers. Hash chains
  prove consistency, not authenticity. The design does not protect against a
  malicious same-UID peer mutating held-directory contents; such mutation is
  detected where the local chain/manifest can detect it and otherwise produces
  reconciliation-required, not a confidentiality or authenticity claim. A
  terminal record is durable storage, not daemon business completion.
- Runner execution remains fail-closed. No process, provider socket, network or
  artifact-service operation is added.

## Compatibility and non-goals

This unpublished 0.1 crate intentionally replaces the current public runner
spool source API and fresh `automonique.runner.event` v1 storage. Every in-tree
caller and test migrates in the same implementation transaction. Fresh code
never emits the legacy format. A private detector recognizes an existing v1
spool and returns `legacy_spool_reconciliation_required` without append,
truncation or guessed mapping; there is no lossless mapping from its five local
kinds to the canonical 23 provider kinds. `SimulationResult` remains the
synthetic simulator's outcome source rather than being reconstructed from a
magic spool payload.

This item may add read-only protocol projections. It does not change the public
agent protocol, resolve raw artifact references, retain/delete records, launch,
normalize vendor payloads, call a daemon/provider, or commit business effects.

## Stop conditions

Stop on a second public event vocabulary; copied protocol types instead of
read-only projections; preview reaching terminal; magic terminal payloads;
sequence gaps/regression or post-terminal append; magic terminal-outcome
inference; any channel escaping the shared quota; unbounded allocation,
`read_to_end`, unchecked arithmetic or raw payload; changing the fixed stderr
rotation without a contract revision; newline framing of unescaped raw bytes;
hash-as-authenticity claims; durable-terminal-as-business-completion claims;
reopened history labeled running without evidence; truncating complete
corruption; trusting stale status; arbitrary paths/symlink following/unsafe
replacement/multiple writers/deletion authority; secret-free content claims;
artifact/provider/network/process activity; execution enablement; a new
registry package/version or lock drift beyond the reviewed direct rustix edge;
unsafe/lint weakening; private-archive/network
access; licence crossing; out-of-lease edits; or a required-check failure whose
repair is outside scope.
