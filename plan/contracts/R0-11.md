## Objective

Measure how interactive shell access and file transfer are actually used, then
record either an accepted isolated compatibility boundary or an explicit
retirement decision. The point is to replace an assumption about what the shell
surface is for with a measurement, so the security boundary is drawn around
observed use rather than imagined use.

The fixture measures and records a decision. It implements no shell, opens no
session, and grants no execution authority.

## Fixture contract

- Usage is measured, not recalled: the fixture records observed interactive
  shell and file-transfer use by class and frequency, and cites how each
  observation was obtained. An unmeasurable class is `null` with a reason
  rather than an estimate presented as data.
- Observations are sanitized at capture. No command containing a credential,
  personal path, customer name, private host or absolute home path is recorded;
  such an observation is recorded by shape and class with a synthetic
  placeholder marked as synthetic.
- The outcome is exactly one recorded decision per usage class: an accepted
  isolated compatibility boundary, or an explicit retirement with its
  replacement and the owner who accepted it. An unresolved class stays
  explicitly unresolved and does not default to either outcome.
- An accepted boundary states what it isolates, what it still permits, and what
  it refuses. A boundary described only as "sandboxed" is not a boundary.
- A retirement decision names the replacement outcome and how a current user
  reaches it. Retiring a class with no replacement path is a finding requiring
  an owner decision, never an implicit removal.
- The fixture replays offline from recorded observations so the decision can be
  re-derived without live access to any host.

## Verification contract

| Check | Expected |
|---|---|
| Usage measurement | shell and file-transfer use is recorded by class and frequency with a cited capture method; unmeasurable classes are `null` with a reason |
| Capture sanitization | no credential, personal path, customer name, private host or absolute home path is recorded; synthetic placeholders are marked synthetic |
| Decision completeness | every usage class carries exactly one recorded outcome, or stays explicitly unresolved; no class defaults silently |
| Boundary specificity | an accepted boundary names what it isolates, permits and refuses; a bare "sandboxed" description fails |
| Retirement path | a retirement names its replacement outcome and how a current user reaches it; a replacementless retirement is a finding |
| Offline replay | the fixture replays from recorded observations with no live host access and reproduces the same decision inputs |
| Quality | the checker runs offline in CI with no network access, no secret and no new runtime dependency |

## Compatibility and evidence

Record measured usage per class with capture methods, the decision recorded for
each class, and the unresolved subset. Report the fixture as input to the
sandbox and shell contracts without claiming either is satisfied.

## Stop conditions

Stop on a recalled usage number presented as measured, a credential, personal
path, customer name, private host or absolute home path entering a recorded
observation, an unmarked synthetic placeholder, a usage class silently
defaulting to a boundary or a retirement, a boundary described only as
sandboxed, a retirement with no replacement path, a fixture that cannot replay
offline, a licence-boundary violation, or any path outside the lease.
