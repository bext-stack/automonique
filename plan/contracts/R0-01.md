## Objective

Produce the machine-readable inventory of every behavioral contract the legacy
system exposes — inputs, state transitions, timers, side effects, commands,
backend events and operational scripts — where each entry carries a named
target owner and a parity fixture plan. This is the evidence base the sanitized
fixture corpus and the parity ledger are built from, so an unowned or
unplannable entry is a finding rather than an omission.

The inventory records *what exists and where it is going*. It does not copy,
paraphrase or reconstruct prior implementation source, and it implements no
replacement behavior.

## Inventory contract

- Permitted inputs are the checked-in `docs/product-plan/` material — in
  particular `reference/legacy-inventory.md`, `reference/feature-parity.md`,
  `reference/migration-plan.md` and `reference/corpus-index.md` — plus the
  structural references the owner authorized: file and module names, directory
  shape, table and column names, and command and environment names. Reading,
  mounting, cloning or searching the private archive is forbidden, and a
  structural reference is not licence to reconstruct the behavior behind it.
- Every entry is classified into exactly one of the seven surface classes:
  input, state transition, timer, side effect, command, backend event and
  operational script. The class set is closed; an observation that fits none of
  them is recorded as an explicit unclassified finding, never forced into the
  nearest class.
- Every entry names a target owner — the Rust crate or module that will own the
  behavior — resolved through the porting map rather than invented. An entry
  whose destination the migration map does not determine is recorded with a
  `null` owner and a reason, not a guess.
- Every entry carries a parity fixture plan naming the fixture class, the
  observable inputs and outputs, and whether a sanitized capture already exists
  in the corpus index. A plan that would require a secret, live network access
  or production write is recorded as blocked with its blocking reason.
- Each entry cites the permitted source that evidences it. An entry without a
  citation is invalid, so the inventory cannot silently accumulate recalled
  claims.
- The inventory is generated and drift-checked: a checker re-derives it from
  its cited sources and fails on divergence in either direction, matching the
  executable-plan-integrity discipline `BOOT-001` established.
- Counts are measured and reported, never estimated. Coverage is stated as
  entries per class with the unowned and blocked subsets named explicitly.

## Verification contract

| Check | Expected |
|---|---|
| Surface coverage | all seven classes are represented; per-class counts are measured; unclassified observations are listed rather than absorbed |
| Owner assignment | every entry resolves an owner through the porting map or records a `null` owner with a reason; no invented destination |
| Fixture plan | every entry names a fixture class, observable inputs and outputs, and corpus status; blocked plans name their blocking reason |
| Source citation | every entry cites a permitted source; an uncited entry fails |
| Clean-room provenance | only permitted inputs are used; no prior source text, control flow or algorithm appears; the private archive is untouched |
| Drift check | the checker re-derives the inventory from its sources and fails on divergence in either direction |
| Quality | the checker runs offline in CI with no network access, no secret, and no new runtime dependency |

## Compatibility and evidence

Record the measured entry count per class, the unowned and blocked subsets, and
the exact permitted sources consulted. Report the inventory as evidence for
`R0-02` and `R0-08` without claiming either is satisfied. A missing measurement
is `null` with a reason; an unowned entry is a finding to report, not a defect
to hide.

## Stop conditions

Stop on any need to read, mount, clone or search the private archive, a
structural reference being used to reconstruct behavior, an entry that cannot
be classified into the closed class set, an invented target owner, a fixture
plan requiring a secret, live network or production write, an uncited entry, a
generated inventory that cannot be drift-checked, an estimated count reported as
measured, a licence-boundary violation, or any path outside the lease.
