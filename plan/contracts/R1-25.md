## Objective

Define the shared Rust value layer every client surface uses to express
interaction: durably identified queued composer input, the retry, undo, stop,
compress and checkpoint intents, per-turn context usage, and the read-only
projections that UI and plugin extensions observe. One typed vocabulary serves
CLI, TUI, dashboard, desktop and messaging clients so a presentation shortcut
can never become a new authority.

This slice defines values, intents, projections and errors only. It performs no
I/O, rendering, transport framing, persistence, provider invocation, context
assembly or actual compression, and it implements no surface.

## Interaction contract

- Queued composer input is a durable item with its own opaque identity, an
  owning session reference, a monotonic queue position and a typed request
  kind. `Steer`, `Retry`, `Reorder`, `Cancel` and `Undo` are distinct kinds
  carrying their own bounded payloads; none is expressible as a mutation of an
  in-memory prompt string. Reordering moves an identified item to an explicit
  position and cannot invent, drop or duplicate an identity.
- `Retry` names the attempt it derives from and produces a successor attempt
  intent. It never addresses, replaces or invalidates prior evidence, and a
  retry of a retry records the original as well as the immediate predecessor.
- `Stop` and `Undo` are idempotent by request identity: repeating an identical
  request yields the same typed outcome rather than a second effect. `Undo`
  names the exact target it reverses and rejects a target that is not
  reversible, rather than silently succeeding.
- `Checkpoint` identifies a restore point by content-addressed digest and
  revision. Creating, listing and restoring are distinct typed operations; a
  restore names the exact checkpoint it targets and cannot be expressed as an
  unqualified "latest".
- Compression is a durable, described operation, never an edit: it carries the
  source range, the compressor provider and model identity, prompt/template
  digest, output digest, the protected facts it must preserve, and an explicit
  verification status. The value layer offers no representation that rewrites
  or elides an authoritative transcript entry.
- Context usage is a per-turn breakdown over a closed set of component classes —
  system policy, rules, skills, memory, tools, MCP, attachments and
  conversation — carrying both estimated and provider-reported token counts as
  separately typed, independently nullable quantities. A missing
  provider-reported count is `null` with a reason and never silently becomes the
  estimate.
- A surface projection is read-only by construction: it exposes observed state
  and carries no method that mutates it. Every action a projection offers is a
  separately authorized typed intent naming the authority it requires. Plugin
  and widget projections are namespaced by extension identity, and a namespaced
  projection cannot name, read or address another extension's namespace.
- Interaction commands are identified by registry command ID shared across
  surfaces. The value layer exposes the identifiers and their bounded
  parameters; it contains no per-surface parsing, regular expression or alias
  table.

Every rejection has a stable typed error category. Bounds are public constants
or const parameters so Rust and generated SDK fixtures can enforce identical
edges without duplicating hidden policy.

## Verification contract

| Check | Expected |
|---|---|
| Queue identity | distinct request kinds are not interchangeable; identities are preserved across reorder; empty, over-bound and duplicate-identity queues fail; position arithmetic is checked |
| Attempt lineage | a retry names its predecessor and the original; no constructor addresses or mutates prior evidence; chained retries preserve both references |
| Idempotent intents | repeated identical stop and undo requests yield one typed outcome; an irreversible undo target fails with its own category rather than succeeding |
| Checkpoint identity | create, list and restore are distinct; restore requires an exact digest and revision; an unqualified or unknown target fails |
| Compression lineage | source range, provider/model identity, prompt and output digests, protected facts and verification status are all required; no value can express a transcript rewrite |
| Context usage | all eight component classes are covered; estimated and provider-reported counts are independently nullable; a null provider count carries a reason and never defaults to the estimate |
| Projection authority | projections expose no mutating method; every action names its required authority; a namespaced projection cannot address another extension's namespace |
| Quality | workspace tests, strict Clippy and formatting pass offline with no new allowance, network access, runtime dependency or lockfile drift |

## Compatibility and evidence

Use only the permitted product requirements, structural migration map, public
Rust behavior and synthetic fixtures. Record actual accepted/rejected case
counts and each error category. If TypeScript fixtures are added under the
Apache-2.0 SDK boundary, record the licence split and require byte-for-byte
agreement with Rust; their absence does not permit claiming cross-language
parity.

## Stop conditions

Stop on an unclear interaction or authority decision, any need for a new
dependency or `Cargo.lock` change, a projection that can mutate observed state,
an action that does not name its authority, a value that can rewrite an
authoritative transcript, an in-memory queue representation without durable
identity, a retry that addresses prior evidence, a non-idempotent stop or undo,
an unqualified checkpoint restore, a silently defaulted token count, an
unbounded payload, a cross-namespace projection read, per-surface parsing
entering the value layer, a network or clock read, a licence-boundary
violation, a forbidden clean-room input, or any path outside the lease.
