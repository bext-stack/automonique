## Objective

Document the identity, data and operations surface the rewrite must carry:
tenants, actor mappings, roles, credentials, artifact classes, workspaces and
dirty trees, retention, budgets, backup dependencies and runbooks. Each entry
records what class of thing exists and who owns it, so identity and policy
contracts have a measured starting point.

The inventory records classes, owners and shapes. It resolves no secret, holds
no credential value, and grants no authorization.

## Inventory contract

- All ten required sections are present: tenants, actor mappings, roles,
  credentials, artifact classes, workspaces and dirty trees, retention,
  budgets, backup dependencies and runbooks. A section with nothing to record
  says so explicitly with a reason rather than being omitted.
- A credential is recorded by class, owner, rotation expectation and storage
  location class only. No credential value, no token, no key material and no
  secret-bearing URL appears in any form, including examples.
- No private infrastructure identifier, customer name, personal email address,
  real host name or absolute home path appears. Where a real value would be
  needed to make a row concrete, the row records its class and a synthetic
  placeholder marked as synthetic.
- Retention and budget entries record the governing policy and its owner rather
  than a recalled number. An unknown value is `null` with a reason.
- Backup dependencies name what a restore requires and in what order, so
  `R0-10` can drill against a real dependency list instead of an assumption.
  The canonical consumer interface is the generated file
  `plan/inventory/surface/restore-dependencies.json`, schema
  `automonique.restore-dependencies/v1`, with `work_item` equal to `R0-09` and
  `consumer` equal to `R0-10`. `R0-10` must verify that the checked-in bytes
  re-derive from the source inventory rather than trusting the export's own
  source digest or accepting an alternate path/schema.
- Every runbook entry names its trigger, its owner and whether an operator
  action is reversible. A runbook step that would touch production is recorded
  as documentation only and is never executable from this inventory.
- The inventory passes the repository scrub before it is committed, so it can
  live in a repository intended to be public.

## Verification contract

| Check | Expected |
|---|---|
| Section coverage | all ten sections are present; an empty section states its reason; per-section counts are measured |
| Credential safety | credentials appear by class, owner, rotation and storage class only; no value, token, key or secret-bearing URL appears anywhere |
| Scrub hygiene | no private identifier, customer name, personal address, real host name or absolute home path appears; synthetic placeholders are marked synthetic |
| Policy provenance | retention and budget rows cite a governing policy and owner, or record `null` with a reason; no recalled number |
| Restore dependencies | backup dependencies name required inputs and their order in a form `R0-10` can consume |
| Runbook safety | every runbook names trigger, owner and reversibility; no step is executable from this inventory and none touches production |
| Quality | the checker runs offline in CI with no network access, no secret and no new runtime dependency |

## Compatibility and evidence

Record measured entry counts per section, the subsets carrying `null` with
reasons, and the scrub result. Report the inventory as input to `R1-13` and
`R0-10` without claiming either is satisfied. A missing measurement is `null`
with a reason, never a zero.

## Stop conditions

Stop on any credential value, token, key or secret-bearing URL appearing in any
form, a private identifier, customer name, personal address, real host name or
absolute home path entering the inventory, an unmarked synthetic placeholder, a
recalled retention or budget number presented as policy, an executable or
production-touching runbook step, a failing repository scrub, a licence-boundary
violation, or any path outside the lease.
