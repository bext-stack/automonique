## Objective

Define the normalized provider event vocabulary and the rules that keep a
presentation stream from becoming a source of truth: the bounded raw provider
envelope, the normalized event kinds, the three-valued authority marking every
record as `preview`, `authoritative` or `synthetic`, the typed provider
approval request and its idempotent response, and the cursor semantics that let
a disconnected consumer resume exactly once.

This slice defines envelopes, events, authority, approval records, cursors and
errors only. It connects to no provider, parses no vendor payload into its
vendor-specific shape, writes no journal, resolves no artifact and drives no
state machine. It fixes what a normalized record *is* so that `R2` and later
can rely on the distinction between what was shown and what was decided.

## Event contract

- A raw provider envelope is bounded and carries provider, binary version,
  protocol mode, schema digest, source event type, source sequence or cursor
  and authority. Payload bytes are size-limited; a record too large to inline
  references an artifact by digest instead of growing. An unbounded raw record
  is unrepresentable, so provider output can never fill durable storage through
  this type.
- Every normalized record carries an Automonique sequence, the provider
  coordinates from `R1-08`, the source event type, the source schema version, a
  timestamp and an explicit authority. Authority is a required three-valued
  field with no default: `preview` is ephemeral presentation, `authoritative`
  is a completed provider message or reconciled history, and `synthetic` is
  Automonique-generated.
- `AssistantPreviewDelta` is `preview` by construction and cannot be marked
  authoritative. Terminal reporting accepts only `authoritative` and
  `synthetic` records; a function that derives a final result from a `preview`
  record does not typecheck. Dropping every preview record from a stream must
  not change the derived terminal outcome, and that is a property test, not a
  convention.
- The normalized kinds cover provider connect and disconnect, session created,
  loaded and updated, turn queued, started, steered, interrupted and completed,
  assistant preview delta and completed message, tool call started, updated and
  completed, approval requested and resolved, subagent started, event and
  completed, usage updated, provider warning and fault, and run terminal.
  Exactly one terminal record may exist per run; a second is a typed conflict,
  not an overwrite.
- Automonique sequence numbers are strictly increasing per run with no
  duplicates and no gaps introduced by the value layer. A consumer cursor
  records consumer identity and topic. Requesting a cursor outside the retained
  range yields an explicit `resync_required` outcome carrying the bounded
  snapshot coordinates — never a silent partial stream and never an empty
  success.
- A `ProviderApprovalRequest` is typed over its class — command, file, network,
  MCP, elicitation or generic permission — and carries the original provider
  request, item and turn coordinates. The response is idempotent: replaying the
  same response with the same coordinates yields the same recorded outcome, and
  a conflicting second decision for the same request is a typed conflict rather
  than a replacement.
- Preview retention is bounded and separately expressible from authoritative
  retention, so expiring previews can never expire the record a report was
  derived from.

## Verification contract

| Check | Expected |
|---|---|
| Envelope bounds | oversized raw payloads are rejected or forced to an artifact reference; an unbounded raw record is unrepresentable |
| Authority is required | no normalized record can be constructed without an explicit authority; there is no default and no inferred value |
| Preview cannot authorize | `AssistantPreviewDelta` cannot be marked authoritative and terminal derivation from a preview record fails to typecheck, proven by compile-fail coverage |
| Preview-drop invariance | dropping every preview record from a synthetic stream leaves the derived terminal outcome unchanged |
| Kind coverage | every listed normalized kind is representable and round-trips; a table proves coverage against the requirement list |
| Terminal uniqueness | exactly one terminal record per run; a second yields a typed conflict rather than an overwrite |
| Cursor semantics | sequences are strictly increasing with no duplicates; an out-of-range cursor yields `resync_required` with snapshot coordinates, never a silent partial or empty success |
| Approval idempotency | a replayed response with identical coordinates yields the identical outcome; a conflicting second decision is a typed conflict |
| Retention split | preview and authoritative retention are separately expressible, and expiring previews cannot expire an authoritative record |
| Quality | workspace tests, strict Clippy and formatting pass offline with no new allowance, network access, runtime dependency or lockfile drift |

## Compatibility and evidence

Use only the permitted product requirements, the recorded `R0-06` provider
surface inventory and synthetic fixtures.
`docs/product-plan/requirements/agent-integrations.md` § Normalized event model
and § Approval bridge, and
`docs/product-plan/requirements/state-and-protocols.md` § Runner event
envelope, are the sources for the kind list, the authority values and the
one-terminal rule. Record the kind-coverage table, per-authority record counts
and every conflict and resync category. A `legacy.runner.event` v1 decoder may
be added only as an explicitly inventoried compatibility codec and is never
emitted for a fresh installation.

## Stop conditions

Stop on any need for a new dependency or `Cargo.lock` change, an unbounded raw
provider record, an authority field with a default or inferred value, any path
where a preview record reaches terminal reporting, more than one terminal
record silently accepted, a cursor gap or duplicate introduced by the value
layer, an out-of-range cursor returning an empty success, a non-idempotent
approval response, preview retention that can expire authoritative evidence, a
network or provider read, a licence-boundary violation, a forbidden clean-room
input, or any path outside the lease.
