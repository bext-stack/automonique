## Objective

Define the typed release manifest that describes exactly one Automonique
release and the compatibility algebra a reload evaluates before it spawns a new
generation: application version, source revision, build target, protocol and
event ranges, database schema range, compatible TypeScript SDK range, the
binary, schema, policy, persona, companion and asset digests, migration
compatibility, and minimum kernel, process-control and optional
supervisor-adapter requirements.

This slice defines the manifest value, its parsing, its digest verification
rules and the range-overlap decision only. It performs no I/O, computes no
digest over a real artifact, selects no release, spawns no generation, runs no
migration and consults no host. A manifest describes a release; it does not
grant authority to install one.

## Manifest contract

- A manifest is parsed into a fully typed value or rejected. There is no
  partially valid manifest and no field that defaults silently: every required
  field is present or parsing fails naming that field. Unknown fields within a
  supported manifest schema revision are preserved for forward compatibility
  and never reinterpreted.
- Version, revision and build target are bounded validated values reusing
  `R1-02` primitives. The manifest carries its own schema revision so a reader
  can refuse a manifest written by a future incompatible writer before
  interpreting any other field.
- Protocol, event and database schema ranges are inclusive `[min, max]` pairs
  over non-zero versions. An inverted or empty range fails at construction.
  Overlap is a typed decision returning the shared sub-range or a no-overlap
  refusal naming both operands, never a boolean.
- Every declared artifact — binary, schema bundle, policy, persona, companion
  and asset — carries a content digest with its named algorithm. A digest of an
  unknown or weakened algorithm is rejected at parse. Verification compares a
  supplied digest against the declared one in constant time and reports a typed
  mismatch that names the artifact but never its contents.
- Migration compatibility declares whether the release's schema range can
  coexist with a named rollback release. A release that cannot coexist with its
  selected rollback target is rejected by the manifest layer, before any
  handoff decision exists to make.
- Minimum kernel, process-control, sandbox and optional supervisor-adapter
  requirements are declared as a typed capability set with explicit
  required-versus-optional status. An unmet *required* capability is a refusal;
  an unmet *optional* one is recorded degradation. The two are separate
  outcomes and a reader may not collapse them.
- The compatible TypeScript SDK range names the schema digest and protocol
  range the SDK was generated against, so an SDK/daemon mismatch is detectable
  from the manifest alone without loading the SDK.
- The manifest contains no secret, no credential value and no absolute host
  path. A credential appears only as a descriptor and version.

## Verification contract

| Check | Expected |
|---|---|
| Field completeness | every required field is enforced at parse with a field-naming error; no required field defaults silently; a table proves coverage of the declared field set |
| Schema revision | a manifest declaring a future incompatible schema revision is refused before any other field is interpreted |
| Range algebra | inverted and empty ranges fail at construction; overlapping, adjacent, disjoint and identical ranges resolve to the declared shared sub-range or a naming refusal |
| Digest discipline | unknown and weakened digest algorithms are rejected at parse; verification is constant-time; a mismatch names the artifact and never its contents |
| Rollback coexistence | a release whose schema range cannot coexist with its selected rollback target is rejected by the manifest layer |
| Capability requirements | unmet required capabilities refuse; unmet optional capabilities record degradation; the two outcomes are never collapsed |
| SDK compatibility | an SDK schema-digest or protocol-range mismatch is detectable from the manifest alone |
| Secret hygiene | no parsed manifest field can hold a secret value or absolute host path; credential fields accept only descriptor plus version, proven by rejection tests |
| Quality | workspace tests, strict Clippy and formatting pass offline with no new allowance, network access, runtime dependency or lockfile drift |

## Compatibility and evidence

Use only the permitted product requirements, the structural migration map and
synthetic fixtures. `docs/product-plan/requirements/target-architecture.md`
§ release manifest and
`docs/product-plan/requirements/state-and-protocols.md` § Database migration
compatibility are the sources for the field set and the coexistence rule.
Record the enforced-field table, the range-algebra case matrix and every
refusal category. Synthetic digests only; no real artifact is hashed in this
slice, and a test that hashes one has left the lease.

## Stop conditions

Stop on any need for a new dependency or `Cargo.lock` change, a required field
that defaults silently, a range comparison returning a boolean instead of a
typed decision, an unknown or weakened digest algorithm being accepted, a
non-constant-time digest comparison, required and optional capability failures
being collapsed, a secret value or absolute host path becoming representable, a
filesystem or network read, a licence-boundary violation, a forbidden
clean-room input, or any path outside the lease.
