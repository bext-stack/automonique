## Objective

Classify every service, path, environment variable, protocol, package, command
and external-platform legacy name as `durable`, `compatibility-only` or
`presentation-only`, so the canonical Rust namespace gate and the
canonical/legacy compatibility contract have one inventory to generate from
rather than several hand-maintained lists.

The inventory records names and their classes. It renames nothing, generates no
compatibility codec, and closes no gate.

## Inventory contract

- The class vocabulary is closed: `durable` names survive into Automonique
  unchanged; `compatibility-only` names exist solely to keep an external or
  stored contract working; `presentation-only` names appear in output and carry
  no stored or wire meaning. A name fitting none is an explicit unclassified
  finding.
- Every entry records its kind — service, path, environment variable, protocol,
  package, command or external-platform name — from a closed kind set, and the
  permitted source that evidences it.
- Every `compatibility-only` entry names the durable identifier it forwards to
  and the reason the compatibility surface exists. A compatibility name with no
  durable counterpart is a failure, because it would forward to nothing.
- Permitted inputs are the checked-in `docs/product-plan/` material and the
  authorized structural references: file and module names, directory shape,
  table and column names, and command and environment names. The private
  archive is never read, mounted, cloned or searched, and a structural
  reference is not licence to reconstruct behavior.
- No entry carries a private infrastructure identifier, personal address, host
  name or absolute home path. External-platform legacy names are recorded by
  their public protocol spelling only.
- The inventory is generated and drift-checked against its cited sources in
  both directions and fails on divergence.

## Verification contract

| Check | Expected |
|---|---|
| Kind coverage | all seven kinds are represented; per-kind and per-class counts are measured; unclassified names are listed rather than absorbed |
| Class vocabulary | only the three classes are accepted; a name fitting none is reported as a finding |
| Forwarding integrity | every compatibility-only entry names an existing durable counterpart and a reason; a dangling forward fails |
| Source citation | every entry cites a permitted source; an uncited entry fails |
| Clean-room provenance | only permitted inputs are used; no prior source text, control flow or algorithm appears; the private archive is untouched |
| Scrub hygiene | no private identifier, personal address, host name or absolute home path appears in the inventory |
| Drift check | the inventory re-derives from its sources and fails on divergence in either direction |
| Quality | the generator and checker run offline in CI with no network access, no secret and no new runtime dependency |

## Compatibility and evidence

Record measured counts per kind and per class, and name the unclassified and
dangling-forward subsets explicitly. Report the inventory as input to `R1-17`
and `R1-19` without claiming either is satisfied.

## Stop conditions

Stop on any need to read, mount, clone or search the private archive, a
structural reference being used to reconstruct behavior, a name that fits no
class in the closed set, a compatibility-only entry with no durable
counterpart, an uncited entry, a private identifier or absolute home path
entering the inventory, an inventory that cannot be drift-checked, a
licence-boundary violation, or any path outside the lease.
