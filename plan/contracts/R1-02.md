## Objective

Implement the dependency-free Rust value layer used by later protocol and
policy work: domain-distinct opaque identifiers, const-bounded UTF-8 text, UTC
epoch-millisecond timestamps, non-zero monotonic revisions, bounded public
HTTP(S) URLs and secret-bearing wrappers. Invalid values fail at construction;
validated values do not expose mutation that can break their invariant.

This slice defines values and errors only. It performs no I/O, parsing of prior
implementation source, identifier generation, clock reads, secret resolution,
authorization, protocol framing or persistence.

## Primitive contract

- `OpaqueId<Domain, const MAX_BYTES: usize>` identifiers are non-empty UTF-8,
  reject a zero `MAX_BYTES`, enforce that public const byte ceiling, and reject
  control characters without otherwise interpreting their contents. Domain
  marker types remain distinct at compile time; display returns the validated
  opaque spelling without assigning meaning to it. A later domain contract may
  narrow its own identifier grammar but cannot weaken the shared bound.
- Bounded text is non-empty valid UTF-8 measured in bytes, has a const maximum,
  and rejects ASCII control characters. It preserves accepted Unicode exactly
  and never truncates or normalizes input silently.
- Timestamps are signed UTC Unix epoch milliseconds with checked conversion to
  and from whole seconds plus a `0..999` millisecond remainder. Arithmetic is
  checked; the value layer does not read a clock or guess a timezone.
- Revisions are non-zero unsigned 64-bit values. Successor creation is checked
  and overflow is a typed error rather than wraparound.
- `PublicHttpUrl<const MAX_BYTES: usize>` rejects a zero `MAX_BYTES`, enforces
  that public const UTF-8 byte ceiling, and accepts only an explicit `http` or
  `https` scheme followed by a syntactically valid, non-empty host. The host is
  an ASCII DNS name, an IPv4 address, or a bracketed IPv6 address; an optional
  port is decimal and in `1..=65535`. Whitespace, empty or port-only authority
  (including `http://:443`), user information, control characters, fragments,
  ambiguous backslashes and raw non-ASCII hosts are rejected. This validates a
  shared stored/wire value; it does not perform DNS lookup, network
  authorization or egress policy.
- `SecretText<const MAX_BYTES: usize>` rejects a zero `MAX_BYTES` and stores
  only non-empty UTF-8 whose length is within that public const byte ceiling;
  no unbounded secret `String` or `Vec` wrapper is exposed. Construction and
  borrowing are explicit, and extraction consumes the wrapper. `Debug` is a
  constant redaction; `Display` and serialization are unavailable; errors name
  only the field and violation class, never the submitted value. Tests use
  synthetic values only.

Every rejection has a stable typed error category. Bounds are public constants
or const parameters so Rust and generated SDK fixtures can enforce identical
edges without duplicating hidden policy.

## Verification contract

| Check | Expected |
|---|---|
| Identifier domains | zero const bounds fail; exact byte-boundary and Unicode values round-trip; empty, one-byte-over and control-containing values fail; unlike domain IDs are not interchangeable |
| Text bounds | byte boundaries, multibyte UTF-8 and control characters are covered with no truncation or normalization |
| Time and revision | negative/zero/positive epoch values, millisecond decomposition, checked arithmetic, non-zero revisions and overflow paths pass |
| URL safety | zero const bounds fail; exact/one-byte-over limits pass/fail; valid DNS, IPv4 and bracketed-IPv6 hosts pass; whitespace, empty/port-only/invalid hosts, invalid ports, credentials, fragments, controls and backslashes fail offline |
| Secret safety | zero const bounds, empty input and one-byte-over input fail; exact-boundary UTF-8 passes; debug and every error contain no synthetic secret; compile-fail coverage proves display/serialization are unavailable |
| Quality | workspace tests, strict Clippy and formatting pass offline with no new allowance, network access, runtime dependency or lockfile drift |

## Compatibility and evidence

Use only the permitted product requirements, structural migration map, public
Rust behavior and synthetic fixtures. Record actual accepted/rejected case
counts and each error category. If TypeScript fixtures are added under the
Apache-2.0 SDK boundary, record the licence split and require byte-for-byte
agreement with Rust; their absence does not permit claiming cross-language
parity.

## Stop conditions

Stop on an unclear identifier grammar or URL security decision, any need for a
new dependency or `Cargo.lock` change, a secret value in formatting/errors/test
output, an unbounded ID/URL/secret representation, a missing exact/over-bound
test, an empty or syntactically invalid URL host being accepted, unchecked
time/revision arithmetic, silent truncation/normalization, a network or clock
read, a licence-boundary violation, a forbidden clean-room input, or any path
outside the lease.
