## Objective

Define the mapping vocabulary that lets ACP, OpenAI-compatible, native Runs,
MCP export, A2A and relay callers reach one durable domain without any of them
becoming a second one: protocol client bindings to tenant actors with scopes,
quotas and credential revisions; the projection of external protocol
identifiers onto canonical work, run and turn identities; and the honest
degradation rules for semantics a foreign protocol cannot express.

This slice defines bindings, mappings and capability declarations only. It
serves no endpoint, terminates no wire format, issues no token and accepts no
connection. Its single most important property is that a compatibility
projection can never create an effect that the canonical domain services do not
already offer.

## Protocol mapping contract

- A protocol client binding carries the protocol dialect, the tenant actor it
  resolves to, its granted scopes, quotas and credential revision. An
  unauthenticated or tenant-free binding is unrepresentable, so every external
  caller — ACP host, OpenAI client, MCP consumer, A2A peer or relay client —
  reaches the domain as an ordinary scoped actor governed by `R1-13`.
- External protocol identifiers map onto canonical work, run and turn
  identities. The mapping is injective per dialect and per client: two external
  identifiers cannot resolve to one canonical identity without an explicit
  aliasing record, and one external identifier never resolves to two.
- No compatibility projection owns state. A projection type has no field that
  is not derived from canonical state and exposes no mutation that is not a
  canonical domain action — proven by compile-fail coverage. There is no
  alternate session store, approval system, tool registry or authorization
  policy, and this is the property the whole contract exists to hold.
- Every effect reachable through a compatibility protocol maps to exactly one
  canonical action with its idempotency key and expected revision, so a
  duplicate external request produces the same `R1-12` receipt rather than a
  second effect.
- Approvals retain their exact targets across the mapping. A host's
  "allow once", a durable allow rule and a deny each map to a typed
  provider or tool approval bound to the original target revision. A global
  bypass mode is unrepresentable — a host cannot enable one because the type
  does not exist.
- Capability declaration is honest per dialect. Each protocol declares what it
  supports, and semantics it cannot represent degrade to bounded text or a
  typed unsupported error while the authoritative record stays intact. Silent
  omission is not an option: an unsupported field returns a typed error rather
  than being dropped.
- A native resource link is expressible from any compatibility projection, so a
  client needing semantics its own protocol cannot represent is pointed at the
  canonical surface rather than served an approximation.
- Remote agent claims are never user approval. An A2A or relay peer's assertion
  about who authorized something carries no authority in the binding type; only
  a resolved tenant actor with scopes does.
- Adjacent releases coexist: each binding declares its supported protocol range,
  and an incompatible client is representable as read-only rather than being
  silently served a mismatched dialect. Unsupported mutations fail closed.

## Verification contract

| Check | Expected |
|---|---|
| Binding completeness | an unauthenticated or tenant-free binding is unrepresentable; every binding carries dialect, actor, scopes, quotas and credential revision |
| Mapping injectivity | two external identifiers cannot resolve to one canonical identity without an explicit aliasing record, and one never resolves to two |
| No alternate state | a projection has no field not derived from canonical state and no mutation that is not a canonical action, proven by compile-fail coverage |
| Effect equivalence | every protocol-reachable effect maps to exactly one canonical action with idempotency key and expected revision; a duplicate external request yields the same receipt |
| Approval fidelity | allow-once, durable allow and deny map to typed approvals bound to the original target revision; a global bypass mode is unrepresentable |
| Honest degradation | unsupported semantics degrade to bounded text or a typed unsupported error; silent field omission is not representable; authoritative records stay intact |
| Native escape hatch | a native resource link is expressible from every compatibility projection |
| Remote claims carry nothing | a remote agent's authorization assertion grants no authority; only a resolved tenant actor with scopes does |
| Range coexistence | each binding declares a supported protocol range; an incompatible client is representable as read-only and unsupported mutations fail closed |
| Quality | workspace tests, strict Clippy and formatting pass offline with no new allowance, network access, runtime dependency or lockfile drift |

## Compatibility and evidence

Use only the permitted product requirements and synthetic fixtures.
`docs/product-plan/requirements/public-agent-protocols.md` — its principle that
adapters terminate wire formats without creating alternate stores, the ACP
approval mapping, the OpenAI honesty rules and the A2A/relay trust boundary —
together with `docs/product-plan/requirements/state-and-protocols.md` § Public
protocols, media and execution backends, are the sources. Record the per-dialect
capability table, the mapping injectivity property test and the compile-fail
cases proving projections own no state and no global bypass exists. Endpoint
behavior is not claimed here; this slice defines the mapping and records that
termination belongs to `R8A` and later.

## Stop conditions

Stop on any need for a new dependency or `Cargo.lock` change, a tenant-free or
unauthenticated binding, a non-injective identifier mapping, a projection field
or mutation not derived from canonical state, a protocol effect without a
canonical action or idempotency key, an approval that loses its target
revision, any representable global bypass, a silently dropped unsupported
field, a remote agent claim granting authority, an incompatible client served a
mismatched dialect, a network or endpoint call, a licence-boundary violation, a
forbidden clean-room input, or any path outside the lease.
