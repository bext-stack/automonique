## Objective

Evolve the existing `automonique_runner::RunSpec` in place into the sole
immutable, versioned execution-admission document. It composes canonical types
already owned by `automonique-protocol` wherever their semantics match; narrow
protocol edits may add missing read-only accessors and canonical projections
but may not widen authority. It does not introduce a parallel `RunSpecV2`.
Concepts that have no matching protocol type are runner-private, bounded and
domain-tagged rather than plain caller strings: workspace-registry ID,
variant-specific protected prompt references, I/O and workspace reservations, profile/persona/
skill/extension/execution-plan digests, scheduler reservation, integration
mode/fallback eligibility, portability/remote-attestation policy, execution
artifact grant, credential audience/version binding, runner event dialect and
direct-versus-automation origin.

The value binds what an admitted attempt is allowed to request before any
protected material is handed off. It contains no prompt bytes, credential
values or ambient authority. A valid value remains non-executable: the current
runner containment refusal must stay in force until later work installs and
attests a descendant-complete boundary.

## Admission contract

- The document has one closed schema identifier, `automonique.run-spec/v1`.
  Construction and decoding both pass through the same validator. Public
  fields remain private, mutation has no public route, and all rejections carry
  a stable typed category.
- The existing `RunSpec` and `RunSpec::new(RunSpecParts)` names are preserved.
  There is no second run-spec type and no duplicate representation of protocol
  concepts.
- The spec binds the work, run, attempt, host and host-lifetime coordinates;
  execution backend and portability policy; a runner-private typed workspace
  registry ID plus the canonical `WorkspaceRegistration` (tenant, source,
  revision, immutable snapshot, isolation and token); the complete canonical
  `SandboxSpec`; provider mode, fallback and required
  capabilities; session or resume coordinates; context/profile/model/tool,
  skill, extension and automation digests; origin and causation; executor,
  executable and protocol digests; artifact and credential descriptors;
  output dialect and approval policy.
- `SandboxSpec` is the single authority for its actor/tenant/provider-account,
  workspace context and base, sandbox/approval policy, path and mount grants,
  provider/tool egress, credentials, budgets, required enforcement features,
  nested isolation and prohibited-capability fields. `RunSpec` does not copy
  them. The validator compares only independently necessary execution
  coordinates — workspace registration tenant/base/isolation and runtime/
  spool reservation — to the authoritative nested values. Missing public
  projections needed for that comparison or for canonical encoding are added
  as read-only protocol accessors in this slice. Workspace
  isolation maps explicitly to the required read-only/write policy.
- Prompt delivery is metadata only: a typed protected-channel/reference
  coordinate names the later R2-02 handoff. `stdin` carries mode only and no
  reference; protected-file and backend-session modes carry distinct,
  non-interchangeable domain-tagged descriptor coordinates, never a filesystem
  path. Prompt bytes never occur in the spec,
  canonical bytes, `Debug`, display text or errors. Credential fields
  contain descriptors, audience and version coordinates only, never secret
  material.
- Paths and platform byte strings have one lossless canonical representation.
  Absolute paths containing empty, dot, dot-dot or NUL components refuse.
  Argument and environment bounds cover item, count and aggregate bytes;
  duplicate environment keys refuse.
- Every duration, byte quota, CPU, memory, PID, I/O, temporary, workspace and
  artifact budget has a public finite bound and checked arithmetic. Zero is
  accepted only where its documented meaning is `disabled`.
- Cross-field validation refuses subject, tenant, workspace, base, policy,
  host-lifetime, backend, session, capability, egress, credential-audience,
  output and approval disagreements. Nested canonical contracts are used as
  typed values rather than being flattened into caller-controlled strings.
- Canonical encoding is canonical JSON built with
  `automonique_protocol::wire`; fixed top-level keys use the field names in the
  normative table below and platform bytes use lowercase hexadecimal. A public
  whole-document ceiling no greater than protocol `MAX_FRAME_BYTES` is checked
  before parsing.
  The decoder rejects missing, unknown and duplicate fields, unsupported
  versions, noncanonical encoded ordering or spelling, widened bounds and
  trailing bytes. Re-encoding a decoded value is byte-identical.
- The whole-spec SHA-256 digest is domain-separated and covers every canonical
  byte. Equal specs have equal digests; a one-field mutation changes it.

## Verification contract

| Check | Expected |
|---|---|
| Encapsulation | rustdoc compile-fail controls refuse private construction and mutation and mixed work/attempt/host identities; paired public getters compile and preserve the typed values |
| Complete valid spec | one full value covers all 20 requirement groups and names the canonical nested contracts used for each group |
| Bounds | exact-limit positives and one-over negatives cover whole-document bytes, identifier/digest, argument item/count/aggregate, environment key/value/count/aggregate, protected reference, duration and every resource quota |
| Cross-field invariants | one-field negatives cover actor/tenant, workspace/base/context/sandbox, timeout/quota, host lifetime/session, origin, executor/backend/fallback/capabilities, egress, credential audience/version, output and approval disagreements |
| Closed codec | a valid round trip is byte-identical; missing, unknown, duplicate, reordered encoded bytes, wrong-type, unsupported-version, NUL, traversal, noncanonical and oversized inputs refuse with typed categories |
| Digest | repeated construction is stable and mutation of every top-level field family changes the whole-spec digest |
| Digest spelling | executable and optional protocol digests accept only canonical lowercase `sha256:` plus 64 hexadecimal digits; wrong algorithm, length, character or case refuses |
| Protected data | prompt bytes and credential values have no structural input route; protected reference fields cannot encode a value; canonical bytes, `Debug`, display and errors expose only bounded metadata. This schema does not claim to classify arbitrary caller argv/environment bytes as non-secret |
| Fail-closed execution | a valid complete spec still returns the existing typed containment refusal and creates no process, network connection, spool or external effect |
| Quality | runner tests, workspace tests, strict Clippy, formatting and diff checks pass offline and locked; lockfile inspection shows only the runner-to-existing-protocol edge and no registry version drift |

Required commands:

```text
cargo test -p automonique-runner --all-targets --locked --offline
cargo test -p automonique-runner --doc --locked --offline
cargo clippy -p automonique-runner --all-targets --all-features --locked --offline -- -D warnings
cargo fmt --all -- --check
cargo test --workspace --all-targets --locked --offline
git diff --check
```

The admitted-base runner baseline is 22 passing tests, zero failures, with
strict Clippy and formatting green. The implementation report records actual
accepted and refused case counts, error categories, the 20-row coverage result,
the exact lockfile delta and reviewer count. Missing measurements remain
`null` with a reason.

## Compatibility and non-goals

This is admission-time schema work only. It performs no path opening,
descriptor ownership or mode check, symlink or TOCTOU proof, protected payload
delivery, process spawn, provider invocation, network I/O, OS sandbox
installation, host attestation, artifact promotion or external effect. Those
belong to later R2 work. Existing fail-closed runner behavior is preserved.

Only the checked-in product requirements, the structural migration map, public
dependency contracts and synthetic fixtures may inform the implementation.
`rust/Cargo.lock` is authorized solely to add the existing local
`automonique-protocol` dependency to `automonique-runner`; no registry package
or version may change. Protocol edits are limited to lossless read-only
projection/canonical-codec support required by the table and paired tests; they
may not add runtime behavior, mutable authority or a second schema.

## Stop conditions

Stop on any protocol edit beyond the narrow read-only projection/codec work
above, any new or updated registry dependency, a second RunSpec, a duplicated protocol type that already
exists or represent a missing domain concept as an untagged string, put
prompt bytes or a credential value in the document, expose a bypass constructor
or mutable field, accept lossy platform strings, leave a required group
unmapped, treat schema validation as use-time containment evidence, weaken the
runner's current execution refusal, access the network or private archive,
cross the licence boundary, touch a path outside the implementation allowlist,
or encounter an unrelated dirty-path overlap.
