## Objective

Create the implementation guides and objective schema consumed by the
executable DAG: clean-room porting, state machines, security boundaries,
naming, test preservation and metrics. Every runnable unit must have a
measurable objective, hill-climbability score and explicit stop conditions.

## Verification contract

| Check | Expected |
|---|---|
| Guide coverage | all six required guide families exist and link to source requirements |
| Objective schema | metric, baseline, budget, tests and stop conditions are required fields |
| Runnable coverage | every runnable program node validates against the schema |
| Low-score refusal | an objective below the configured hill-climb threshold is non-runnable |
| Contradictions | conflicting guide rules fail with both source locations |
| Reproducibility | guide/objective manifest regenerates byte-identically |

## Forbidden shortcuts

- generic advice that cannot fail validation;
- converting missing evidence to zero/pass;
- lowering objectives or tests to raise hill-climbability;
- copying prior implementation source or behavior descriptions beyond allowed inputs.

## Completion evidence

Guide manifest, schema validation counts, low-score and contradiction failure
fixtures and deterministic regeneration result.

## Stop conditions

Stop when a guide requires an owner policy choice not already present in the
permitted specification; record the unresolved choice rather than inventing it.
