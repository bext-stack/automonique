## Objective

Prove the self-hosting recovery boundary by drill rather than assertion:
deliberately corrupt or crash candidate development state and, separately,
stable development state; restore from the last seed or recovery bundle;
reconcile repository heads against evidence; and demonstrate that neither
failure nor recovery can reach production. The drill is executable and
rerunnable, so the recovery path is exercised routinely instead of first being
tried during a real incident.

The drill operates only on synthetic development state it creates itself. It
never damages the working repository, never touches a production system, and
performs no promotion.

## Drill contract

- The drill builds its own disposable fixture state and asserts before starting
  that it is not operating on the live repository, the configured remote or any
  production path. It refuses to run rather than proceeding when that assertion
  cannot be made.
- Candidate corruption is exercised as its own scenario: with candidate state
  damaged, stable must ignore that state and either reconstruct candidate
  projections from signed source and evidence or abandon the namespace. A
  candidate that corrupts itself must not be able to damage stable.
- Stable-development corruption is a separate scenario: recovery starts
  disconnected, restores the latest consistent development backup, and does not
  activate any candidate until action receipts and repository heads reconcile.
  Activation before reconciliation is a drill failure, not a warning.
- Crash is distinct from corruption: an interrupted operation is killed at a
  chosen point and the drill asserts the surviving state is one of the declared
  legal states, with no partially applied effect and no lost durable receipt.
- The recovery bundle is verified as independent: it carries checksums and
  operator instructions, and restoration is proven from the bundle alone
  without reading the damaged state it replaces. A bundle that cannot be
  verified is a failure, not a fallback.
- Reconciliation compares repository heads, action receipts and evidence
  digests and reports an explicit typed outcome. An ambiguous outcome is
  reported as ambiguous and reconciled by receipt; it is never resolved by
  retry.
- Production isolation is asserted positively in every scenario: the drill
  records the exact ambient authority it held and demonstrates that no
  production credential, remote, branch or deployment path was reachable at any
  point.
- The drill is idempotent and leaves no residue: rerunning yields the same
  outcomes, and it cleans up its fixture state on both success and failure.

## Verification contract

| Check | Expected |
|---|---|
| Safety refusal | the drill refuses to start when it cannot prove it is operating on disposable fixture state rather than the live repository or remote |
| Candidate corruption | damaged candidate state is ignored by stable, which reconstructs from signed source and evidence or abandons the namespace; stable is provably undamaged |
| Stable corruption | recovery starts disconnected, restores the latest consistent backup, and refuses candidate activation until receipts and heads reconcile |
| Crash boundary | an interrupted operation leaves one of the declared legal states with no partial effect and no lost durable receipt |
| Bundle restore | the recovery bundle verifies by checksum and restores without reading the damaged state; an unverifiable bundle fails |
| Reconciliation | heads, receipts and evidence digests produce an explicit typed outcome; ambiguity is reported and receipt-reconciled, never retried |
| Production isolation | every scenario records the ambient authority held and proves no production credential, remote, branch or deployment path was reachable |
| Rerun hygiene | a second run reproduces every outcome and leaves no fixture residue after either success or failure |

## Compatibility and evidence

Record each scenario's injected fault, observed surviving state, restore
source, reconciliation outcome and measured wall time. Report the drill as
evidence for the self-hosting recovery boundary without claiming any promotion,
gate closure or production readiness. A scenario that could not be run is
`null` with a reason, never a pass.

## Stop conditions

Stop on any inability to prove the drill targets disposable fixture state, a
scenario that would touch the live repository, configured remote or a
production path, candidate damage propagating into stable, candidate activation
before reconciliation, a partially applied effect or lost receipt after a
crash, an unverifiable recovery bundle used as a fallback, an ambiguous
reconciliation resolved by retry, any reachable production credential, residue
left after a run, a licence-boundary violation, or any path outside the lease.
