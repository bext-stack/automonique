## Objective

Prove the portable control-plane lifecycle with directly launched foreground
processes: readiness, replacement warm-up, failed replacement fallback,
bounded drain, signal handling, and clean shutdown. No service manager,
self-daemonization, persistent unit, or privileged operation is involved.

## Scope

In scope:

- synthetic old/new foreground generations below `spikes/foreground-lifecycle/`;
- a typed local readiness/handoff channel;
- forced failure before and after readiness;
- bounded drain, signal handling, child cleanup, and machine-readable events;
- explicit comparison points for optional supervisor adapters.

Out of scope: choosing a production supervisor, installing a service, opening a
production socket, loading credentials, or implementing product behavior.

## Verification contract

| Check | Expected |
|---|---|
| Environment | kernel, runtime, immutable base, timeout and cleanup plan recorded |
| Successful handoff | old generation remains active until new readiness, then drains and exits |
| Pre-ready failure | failed replacement leaves the old generation active |
| Post-ready failure | durable ownership converges without two active owners |
| Foreground control | readiness and shutdown use typed process/protocol events, not service-manager state |
| Cleanup | no fixture process, socket or temporary state survives |

## Forbidden shortcuts

- treating process start as readiness;
- sleeping without bounded state observation;
- installing a service or relying on supervisor-specific notification fields;
- asserting cleanup after killing only a parent PID.

## Completion evidence

Fixture source, exact invocation, state transitions, injected failures,
shutdown latency and cleanup verification. Review count may be zero and is
recorded truthfully.

## Stop conditions

Stop before mutation if isolation from unrelated processes cannot be proved,
if the fixture requires privilege, or if a portable lifecycle field is missing.
